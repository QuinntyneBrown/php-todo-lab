Button

Buttons let people act: add a task, clear completed ones, undo a delete, try a failed load again. One primary button per view says what the screen is for.

Overview

Use a button when activating it changes something: it adds, clears, deletes, undoes or retries. Use a link when it only takes the person somewhere. Use a button group when several mutually exclusive options choose a view, as the All / Active / Done filter does.

  • Primary is the one action the view exists for. In v1 that is Add task, and nothing else is primary.
  • Secondary (the default look, an outlined button) is for other real actions. Inside an alert it takes the alert's tone, which is how Try again in the load-error banner is drawn.
  • Ghost is accent text with no container until hover. It sits in dense surfaces: Clear completed in the toolbar and Undo in the toast.
  • Link looks like a link but behaves like a button; use it for low-emphasis actions inside sentences.
  • Danger is a solid destructive button. v1 never uses it, because deletes are undone from a toast instead of confirmed (L2-022). It exists for a future confirmation step.
  • Ghost danger is a quiet icon button that turns red only on hover or focus: the per-row Delete.

Anatomy

  1. Leading icon (optional)20px, 2px stroke, currentColor, aria-hidden. Stays visible when the label collapses below SM.
  2. Label.btn__label. A verb phrase in sentence case, semibold 16px (--text-button); the accessible name.
  3. ContainerHeight from --control-height-* (36 / 44 / 52px), 1.5px edge, --radius-md (12px), padding --space-3/4/5.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Primary, secondary, ghost, link, danger, ghost danger (icon-only).

In context

Task deleted

Couldn't load your tasks. Check your connection and try again.

Inside a toast, ghost takes the inverse accent; inside an alert, secondary takes the alert's tone. No extra classes are needed.

With icons, icon-only, block and collapsing

.btn--collapse shows only its icon below 576px; resize the window to see it. Icon-only buttons always carry aria-label.

Sizes

Medium (44px) is the default and the product's minimum touch target (L2-028.1). Large (52px) is the composer's Add task, matching the 52px input beside it. Small (36px) is only for places where the surrounding row is itself the 44px target.

Heights --control-height-sm/md/lg; padding --space-3/4/5; small also drops to --font-size-sm.

States

Pointer and focus states are forced here with data-state; real pages get them from :hover, :focus-visible, :active, :disabled, aria-disabled and aria-busy.

Pressed and expanded

aria-pressed="true" tints with the accent; aria-expanded="true" holds the hover fill while its menu is open.

Both themes

  • Loading keeps the width, hides the label, shows a ring in the label colour, sets aria-busy="true" and ignores clicks. v1 is optimistic (L2-004), so loading is reserved for Try again while the list reloads.
  • Disabled (disabled) is removed from the tab order and is 55% opaque. Use it only when a pending row is waiting for the server (L2-004.1).
  • Aria-disabled (aria-disabled="true") looks the same but stays focusable, so its state can be discovered. Clear completed uses it when there is nothing to clear (L2-017.2); the click handler returns early.

Responsive behaviour

  • XS (< 576px): Add task collapses to its plus icon (.btn--collapse), a 52px square; the accessible name stays on aria-label="Add task". Clear completed wraps onto its own line under the full-width filter and aligns right.
  • SM and up (≥ 576px): Add task shows its label; the toolbar holds the filter and Clear completed on one row.
  • Hover-capable pointers: the row's Delete is hidden until the row is hovered or has focus inside it. On touch (hover: none) it is always visible (L2-028.2).
  • Labels never truncate or wrap; a label that does not fit at 320px is too long.
  • Every product button is at least 44 × 44px at every breakpoint (L2-028.1); small (36px) never appears in the product.

Theming

The button reads only component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-fg-hover, --btn-bg-active, --btn-ring, plus --btn-height, --btn-pad, --btn-radius), which alias semantic tokens. Each variant overrides them; containers do too, which is how the toast and the alert re-tone their buttons without new classes.

/* What .toast does to the buttons inside it */
.toast .btn { --btn-fg: var(--toast-action); --btn-bg-hover: var(--toast-action-hover); --btn-ring: var(--toast-action); }

In dark, the accent lightens to sea-400 and the label flips to --color-fg-on-accent (deep sea, 8.1:1). Hover replaces the mock's filter: brightness(1.08) with --color-accent-hover, which is lighter in dark and darker in light, so both themes keep their contrast (D6).

Accessibility

Role and pattern

Native <button type="button">, or type="submit" for Add task inside the composer form. Toggle buttons follow the APG Button pattern with aria-pressed. Never a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order. aria-disabled buttons stay in the order; disabled ones do not.
Enter, SpaceActivates. Enter in the composer field also submits Add task.
Ctrl/Cmd+ZSame as the toast's Undo while it is showing (L2-015); the toast never takes focus.

Focus

One ring for everything: 2px --color-focus-ring at a 2px offset on :focus-visible (L2-030.2), so pointer clicks do not show it. Inside the toast the ring takes the action colour so it stays visible on the inverse surface.

Labelling

The visible label is the name. Icon-only buttons carry an aria-label that includes the task title: "Delete Call mom" (L2-029.5). The collapsing Add task keeps aria-label="Add task" at every width. Loading keeps the name; progress is announced through the page's polite live region, not the button.

Motion

Background, border and colour transition over --duration-fast (150ms); active scales to 0.97. Reduced motion zeroes the durations in the tokens, so both become instant. The loading ring stops rotating and reads as a static ring next to the busy state.

Touch

Medium and large exceed 44 × 44px (L2-028.1). Icon-only buttons are 44px circles even though the icon is 20px. Delete is always visible where there is no hover (L2-028.2).

Content

  • Verb phrases in sentence case, one name per thing (L2-025): "Add task", "Clear completed", "Undo", "Try again". Never "OK", "Submit" or "Click here".
  • The verb on the button matches the announcement it causes: Add task → "Task added"; Clear completed → "3 tasks cleared".
  • Icon-only labels name the object: "Delete Call mom", not "Delete" or "Trash".
  • Destructive labels name the loss: "Delete 3 tasks", not "Confirm".
  • No exclamation marks; loading never changes the label.
