Task item

One task: a checkbox that completes it, a title that edits in place and a delete button. Completing a task is the moment the app celebrates.

Overview

A task item is one row of the list: a native checkbox that completes the task, a title that edits in place, and a delete button. It is the product's signature component; completing a task is the one moment the app celebrates (L2-011).

  • Use it only inside .task-list on a card. For any other list of things use the generic list.
  • The row itself is not a control. Its three children are, each with its own accessible name that includes the task title (L2-029.2, L2-029.5).
  • Newest first; completing a task does not move it. In a filtered view a task that no longer matches leaves with the leave animation (L2-006.6).

Anatomy

  1. Checkbox.checkbox--round: 24px ring inside a 44px target; tick drawn with stroke-dashoffset; one sun-coloured burst on completion.
  2. Title.task__title-btn: a real button that starts editing; wraps on every line; strike wipes left to right when done.
  3. Delete.btn--icon.btn--ghost-danger, 44px; hidden until hover or focus on pointer devices, always visible on touch.
  4. Row60px minimum height, 4/8px padding, 1px --color-border-default divider, --color-bg-subtle on hover.

Variants

A task is either active or done. Done is not only a colour: the circle fills, the tick is drawn and the title is struck through and muted, so state never relies on colour alone (L2-030.6).

Active and done. The done title stays at 5.9:1 (light) and 7.3:1 (dark).

Long title

200 characters wrap onto as many lines as they need; the checkbox and delete stay aligned and never overlap the text (L2-027.6).

Editing

  • A task needs a title.

The title becomes a text field in the same cell; an empty save restores the title and explains why (L2-013.2).

Sizes

Task items have one size: a 60px minimum row with 44px targets (L2-028.1). Long titles grow the row instead.

States

Pointer and focus states are forced with data-state and motion is frozen with data-frozen, mirroring states.row. Real pages get them from :hover, :focus-visible, :focus-within, checked and aria-busy.

Completing, frame by frame

The whole sequence fits in 500ms (--duration-base fill and tick, --duration-slow strike, --duration-deliberate burst). The script adds .checkbox--burst for one cycle; data-frame exists only to show the frames here.

0 ms
Unchecked.
~150 ms
The circle fills, the tick starts drawing, the burst leaves the checkbox.
~300 ms
The tick is drawn, the burst fades, the strike wipes across.
≤ 500 ms
Completed (L2-011.2, L2-024).

Both themes

Responsive behaviour

  • XS (< 576px): the row spans the full card width inside the 16px page gutter; long titles wrap and the row grows (L2-027.6). Tested at 320px with a 200-character title.
  • SM to XL: the card caps at 560px (SM) and 640px (MD+) via --layout-container-max; the row never stretches wider.
  • Touch (hover: none): delete is always visible. On hover: hover devices it is revealed on row hover or :focus-within (L2-028.2).
  • Every target is 44 × 44px (checkbox control, delete); the title button's hit area is the text plus 8px padding and the row is 60px tall (L2-028.1).
  • Orientation changes keep edit state: the field is the same element, only the layout reflows (L2-028.4).

Theming

The row reads only semantic tokens: --color-bg-subtle for hover, --color-border-default for the divider, --color-fg-muted for done titles, --color-accent and --color-fg-on-accent for the checked circle and tick, --color-highlight for the burst, and the danger tokens through the delete button. Its one component token is --task-min-height.

/* A denser list for a future screen, without touching .task */
.task-list--dense .task { --task-min-height: var(--target-comfortable); }

In dark the accent lightens to --palette-sea-400 and the tick flips to near-black --palette-sea-950 (8.1:1); the hover tint becomes the darker sunken surface, matching the mocks.

Accessibility

Role and pattern

A <li> in a <ul class="task-list"> (L2-029.1) holding three native controls: <input type="checkbox"> (APG Checkbox, native), a <button> for the title and a <button> for delete. Editing swaps the title button for an <input type="text"> in the same cell. No ARIA roles are added.

Keyboard

KeyAction
Tab / Shift+TabCheckbox, then title, then delete, then the next row.
SpaceOn the checkbox: completes or reopens the task.
EnterOn the title: starts editing with the text selected. In the field: saves.
EscIn the field: cancels and restores the title; focus returns to the title button.
Enter / Space on deleteDeletes the task; a toast offers Undo for 6 seconds. Ctrl/Cmd+Z also undoes (L2-015).

Focus

Each control shows the shared 2px --color-focus-ring with a 2px offset (D16 removed the mock's 3px). After delete, focus moves to the next row's checkbox, or the previous row's when the last one is deleted, or the composer when the list empties. After Escape or save, focus returns to the title button.

Labelling

Checkbox: the task title (L2-029.2). Title button: "Edit <title>". Delete: "Delete <title>" (L2-029.5). The edit field: "Edit task title"; its error is linked with aria-describedby and set aria-invalid="true". Completions and edits are announced in the polite live region ("Task completed", "Task updated"); errors use role="alert" toasts.

Motion

Only transform, opacity, background-size (strike) and stroke-dashoffset (tick) animate (L2-024.3). Under prefers-reduced-motion the tokens zero every duration, so the task is simply checked and struck through with no burst, and rows appear and disappear without sliding (L2-024.2).

Touch

Checkbox and delete are 44 × 44px; delete is always visible on hover: none devices; actions fire on click, never on pointer down. The 4px gap between targets is within the 44px boxes, which already exceed the 24px minimum.

Content

  • The title is the user's text, shown as typed; nothing is truncated or capitalised.
  • Accessible names repeat the verb from the UI: "Edit Call mom", "Delete Call mom" (L2-025.2).
  • The empty-edit message is exactly "A task needs a title." — it states the problem; the title is restored, so no next step is needed.
  • Toasts after a row action use the same nouns: "Task deleted" with Undo; failures say "Couldn't delete that task." without apologising.
