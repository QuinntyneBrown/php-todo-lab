Pattern

Feedback and loading

Change first, confirm quietly, offer Undo, and revert loudly only when something failed.

Overview

Every action in Tasks shows its result within 100 ms (L2-039.1) because the interface changes first and asks the server second. This page decides which feedback each action gets: an immediate change in place, a polite announcement, an Undo toast, an error toast, or an inline banner.

  • Optimistic by default: add, complete, reopen, edit, delete and clear update the list and counts at once (L2-004, L2-010, L2-013, L2-015, L2-017).
  • Revert on failure: if the write fails, the change is undone and an error toast says what did not happen. Writes are never retried automatically (L2-042.2).
  • Undo instead of confirm: delete and clear completed act immediately and offer Undo for 6 seconds. No confirmation dialog exists (L2-022).
  • Skeleton, not spinner: the first load shows three skeleton rows and a usable composer (L2-008.1).

Components: Toast, Alert, Skeleton, Task item, Progress, Spinner, Inline message.

Rule of thumb: confirm with the change itself; announce it for screen readers; add a toast only when the person may want to reverse it (Undo) or when something they did not see failed.

Responsive behaviour

  • Toasts sit at the bottom centre at every breakpoint, full width minus 16px gutters up to 420px, above env(safe-area-inset-bottom) (L2-028.5).
  • The list keeps 96px of bottom padding (--layout-safe-bottom) so a toast never covers the last row or its focused control (WCAG 2.4.11).
  • Skeleton rows match the 60px task row height, so nothing shifts when the list arrives.
  • The load-error banner wraps its button under the text below about 400px of card width.

Accessibility

Feedback that is only visual is not feedback. Every change has a matching announcement in one polite live region (aria-live="polite", owned by the page) plus the toast's own role:

  • Toasts never take focus (L2-031.5). Ctrl/Cmd+Z triggers Undo while the toast is visible.
  • After a keyboard delete, focus moves to the next row, the previous row, or the composer (L2-031.3).
  • Pending rows set aria-busy="true" and disable their controls until the server answers.
  • With reduced motion the shimmer becomes a static tone and every transition is instant (L2-024.2); state is still shown by tick, strike and text.

Content

  • Success toasts are past tense and name the thing: "Task deleted", "3 tasks cleared", "1 task cleared" (singular when n is 1).
  • Error toasts say what did not happen and, when it helps, what to do: "Couldn't add that task. Try again."
  • The verb matches across button, toast and announcement: "Add task" → "Task added" (L2-025.2).
  • Never "Oops", never "Sorry", never an exclamation mark.
