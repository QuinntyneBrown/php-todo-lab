Spinner

A small rotating ring for a short wait of unknown length on one control or region.

WCAG 2.2 AAStatus: stableNot used in v1

Overview

A spinner says "working on it" for a short wait whose length is unknown and whose result will replace one control or a small area. v1 does not use a spinner: the list loads behind skeleton rows (L2-008.1) and every change is optimistic, so nothing waits on screen. It is part of the core set for future flows (D22) and is what .btn[aria-busy="true"] draws.

  • Use a skeleton when the shape of the coming content is known.
  • Use a progress bar when progress can be measured.
  • Use a spinner for a pressed button or a small region, for under a few seconds.

Anatomy

  1. TrackFull circle, --border-width-thick, --color-border-default.
  2. HeadTop quarter in --color-accent; rotates once per 900ms (2 × --duration-deliberate).
  3. TextWhat is loading, in muted 14px; required unless the spinner sits inside a labelled busy button.

Sizes

Small 16px (inline with 14px text), medium 20px (default, matches icons), large 32px (a region).

States

A spinner has one state: running. It is never focusable, hovered or disabled. Remove it when the wait ends.

Responsive behaviour

  • Sizes do not change with the viewport. A region spinner is centred in the area it replaces and keeps that area's height so nothing jumps.
  • Inline spinners wrap with their text like any inline content.

Theming

Track --color-border-default, head --color-accent. Inside a button the spinner is drawn by .btn[aria-busy]::after in --btn-fg, so it follows each button variant. Size via --spinner-size.

Accessibility

Role and pattern

A role="status" container with text (visible or .visually-hidden) announces the wait politely; the spinner graphic is aria-hidden. In a button, aria-busy="true" on the button plus a status message in the form's live region. There is no APG pattern for spinners; this follows the APG Alert guidance for live regions, in the polite form.

Keyboard

Nothing to operate: the component is not focusable.

Focus

Focus stays on whatever started the wait. A busy button keeps focus and ignores further activation.

Labelling

Say what is loading: "Loading tasks", never "Loading…" alone.

Contrast

Head on card
Inline text

Motion

Rotates continuously. Under prefers-reduced-motion the rotation stops and the static partial ring plus its text still read as "busy" (D21).

Touch

Not interactive.

Content

  • Name the thing: "Loading tasks", "Saving".
  • No ellipsis-only labels, no "Please wait".
  • If a wait passes ten seconds, replace the spinner with an explanation and a way out.
