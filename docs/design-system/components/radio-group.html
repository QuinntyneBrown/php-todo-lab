Radio group

A radio group asks for exactly one choice from a short, visible set. It is the form counterpart of the segmented filter: same rule, one selection, but the choice waits for submit.

WCAG 2.2 AAStatus: stableNot used in v1Native <input type="radio">

Overview

Use a radio group when people must pick one of two to six options and seeing every option helps them choose. Use a select for longer lists, a checkbox when several can be chosen, and the segmented button group when the choice applies immediately and filters what is on screen.

Not used in v1. Tasks has one screen (L2-022) and its only one-of-many choice, the All / Active / Done filter, applies instantly, so it is a segmented button group with aria-pressed (L2-029.4 allows either; the group keeps one Tab stop per button and shows counts). The radio group is documented so a future settings form stays consistent with the system.

Anatomy

  1. Legend<legend class="choice-group__legend">: the question, --text-label. Required, because it names the group.
  2. Target.radio__control: 44 × 44px hit area with the native input stretched over it.
  3. Dot.radio__dot: 24px ring in --color-border-strong; the selected ring turns accent and a 10px accent dot scales in.
  4. LabelText inside the <label>, so the whole line is clickable.

Variants

Vertical is the default and the easiest to scan. Horizontal is only for two or three short options. Cards are for options that need a description.

Both themes

Responsive behaviour

  • XS: every group is vertical; .choice-group--horizontal wraps onto new lines rather than shrinking targets.
  • SM and up: horizontal groups sit on one line when the options fit; never more than three.
  • Choice cards are full width at every breakpoint; from MD two cards may sit side by side in a .form__row--split.
  • Targets stay 44px at all breakpoints; labels wrap, they never truncate.

Theming

Reads --color-border-strong (ring), --color-accent (hover, selected ring and dot), --color-bg-surface (fill), --color-danger-solid (invalid) and, for cards, --color-border-default and --color-accent-subtle. Both themes swap only these semantic tokens; no radio-specific dark rules exist.

Accessibility

Role and pattern

Native radios sharing a name, inside <fieldset> with <legend>: the APG Radio Group pattern without any ARIA.

Keyboard

KeyAction
Tab / Shift+TabEnters the group on the checked radio (or the first when none is checked) and leaves it; the group is one Tab stop.
↓ → / ↑ ←Moves to and selects the next / previous option, wrapping.
SpaceSelects the focused option when none is selected yet.

Focus

The shared 2px ring with 2px offset is drawn on the dot. On a card, the dot carries the ring too, so the focus indicator does not depend on the card's tint.

Labelling

The legend is the group's name; each option's text is its name; card descriptions use aria-describedby. A group error goes on the fieldset with aria-describedby and every radio gets aria-invalid="true".

Motion

The dot scales in over --duration-base; reduced motion zeroes it so selection is instant.

Touch

Each option is a 44px-tall label, and the whole label is the target.

Content

  • The legend is a short question or noun phrase in sentence case: "Show on open", not "Please select an option".
  • Options are parallel and mutually exclusive; order them logically (most common first, or natural order like days).
  • Preselect the safest common option unless the choice must be deliberate.
  • Error copy says what to do: "Choose what to show when the app opens." Never apologise (L2-025).
