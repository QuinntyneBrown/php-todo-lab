Foundation · Colour

Color

Blue-grey ink, one sea-green accent, sun for celebration, red for failure: every colour is a token with a light and a dark value, and every pairing is checked.

WCAG 2.2 AAStatus: stableSource: tokens/tokens.css

Overview

Colour in Tasks is quiet on purpose: blue-grey ink on a misty canvas, one sea-green accent for the things you act on, sun yellow only for the moment a task is done, and red only when something failed. Every colour is a token; nothing in the product or the mocks names a hex value outside tokens/tokens.css (L2-026).

  • Primitives (--palette-*) are the five ramps below. Components never read them.
  • Semantic tokens (--color-*) say what a colour is for. Both themes define the same names with different values; components read only these.
  • Component tokens (--btn-bg, --input-border, --toast-bg …) live in assets/components.css and alias semantic tokens.

The product follows prefers-color-scheme with no toggle (L2-026). The toggle in this sidebar and the side-by-side panels exist for review only.

Primitive ramps

Ink

The blue-grey neutral (hue ≈ 207°). Every surface, line and text colour in both themes.

Sea

The accent: primary actions, checked tasks, focus, progress, links.

Sun

Celebration and caution: the completion burst, illustration highlights and the offline notice. Never text on light surfaces.

Red

Danger: errors, invalid fields, the delete hover and the error toast.

Blue

Info. No mock uses it yet (D22); derived from the ink hue so it sits quietly beside the neutrals.

White

--palette-white is the light surface and the label on the light-theme accent.

Steps marked added in tokens.css were introduced during extraction to fix a contrast failure or fill a missing role: ink-450 (D1), ink-850 (dark raised surface), sea-100/200/800/850 (hover and active states that the mocks produced with filter, D6), sun-200/300/700/800/900 (warning roles) and red-100/200/800. Dark --ink and light --mist were merged into ink-50 (D4); dark --paper and light --ink into ink-900 (D5).

Semantic roles

Each role in the light theme (left) and the dark theme (right). The dark theme is built from roles, not by inverting: surfaces get lighter as they rise, the accent lightens to sea-400 and the label on it flips to near-black sea-950.

Status colours

Four statuses, each with five roles: bg (tinted panel), fg (text on that panel or on a card), border (decorative edge), icon (≥ 3:1 on its bg) and solid (filled badges and destructive buttons). Status is always colour + icon + words (WCAG 1.4.1).

  • Danger carries every error: field messages, the load-error banner, the error toast, the delete hover.
  • Warning is the offline notice. Its text stays --color-fg-default (as in the mock) and its icon now uses --color-warning-icon (D19).
  • Success reuses the sea ramp: done is the accent's own meaning in this product.
  • Info has no mock yet (D22).

Adding a brand theme

A theme is a block that overrides semantic tokens only. Add primitives if the brand needs new hues, then map roles:

/* tokens.css */
:root { --palette-plum-600: …; --palette-plum-700: …; --palette-plum-50: …; }
[data-theme="plum"] {
  --color-accent: var(--palette-plum-600);
  --color-accent-hover: var(--palette-plum-700);
  --color-accent-subtle: var(--palette-plum-50);
  --color-fg-accent: var(--palette-plum-700);
  --color-fg-link: var(--palette-plum-700);
  --color-focus-ring: var(--palette-plum-600);
}
  1. Override every role that derives from the accent (accent, hover, active, subtle, subtle-hover, fg-accent, fg-link, link-hover, focus ring, success if it reuses the accent).
  2. If the theme can be dark, add a dark variant of the block ([data-theme="plum-dark"]), built from roles.
  3. Run check_contrast.py tokens/tokens.css; every pair must pass in every theme before the theme ships.
  4. Regenerate tokens.json with tokens_to_json.py.

See Theming for how themes are selected.

Usage

  • Read semantic tokens only. var(--palette-sea-600) in a component is a bug; var(--color-accent) is not.
  • One accent per view does the talking: Add task, the checked state, the progress ring. Ghost actions use --color-fg-accent text, not a filled accent.
  • --color-highlight (sun) is decoration: the completion burst and empty-state art. Never text, never the only signal.
  • Muted text (--color-fg-muted) still passes 4.5:1 everywhere it sits; completed tasks rely on muted colour and the tick and strike-through (L2-030.6).
  • Danger appears only when something failed or is about to be destroyed; the delete icon is muted until hovered.
  • Borders that identify a control use --color-border-strong (≥ 3:1). --color-border-default is for dividers, which are decorative.

Accessibility

  • 1.4.3: all text pairs ≥ 4.5:1 in both themes (see Contrast pairs). The lowest light-theme text pair is --color-fg-on-accent on --color-accent at 4.88:1.
  • 1.4.11: control boundaries and the focus ring ≥ 3:1. The mocks' --line-strong missed this (2.89:1, D1) and the composer input had no boundary at all (D2).
  • 1.4.1: status and completion never rely on colour alone.
  • prefers-contrast: more raises borders to strong and muted text to default; forced-colors: active hands borders and the focus ring to system colours.
