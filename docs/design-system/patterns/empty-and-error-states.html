Pattern

Empty and error states

Five ways the list can have nothing to show, each with its own look and one plain sentence about what to do next.

WCAG 2.2 AAUsed in v1L2-007.3, L2-008, L2-042.3

Overview

Every data state of the list has a designed treatment with plain, actionable copy (L2-008). The card's frame (composer, toolbar) never disappears: only the list region changes, so the person always has the composer to act with.

There are five distinct situations, and they look different on purpose: first run (nothing exists yet), filter empty (tasks exist but none match), all done (a success, shown in the header, not as an empty list), load error (we could not fetch the list) and offline (we can fetch nothing new; existing tasks stay).

Components: Empty state, Alert, Progress, App header, Skeleton, Error page.

Structure

Nothing here yet

Type a task above and press Enter.

First run: frame first, then illustration, title, one sentence. No button, because the composer above is the action.
  1. Illustration: 88px inline SVG, aria-hidden, drawn with .art-fill, .art-line, .art-highlight. Decorative only.
  2. Title: a short statement in the display face (--text-h2).
  3. Text: one sentence, at most 30ch wide, telling the next step.
  4. Action (optional): only when the next step is not already on screen. In v1 it always is.

Responsive behaviour

  • The empty state is centred in the card at every width; text wraps at 30ch, so the line length is the same on a phone and a desktop.
  • The illustration stays 88px; below 360px the block padding shrinks with the card, not the art.
  • The load-error alert wraps its Try again button under the message when the card is narrow (flex-wrap, body basis 12.5rem).
  • The offline notice sits above the card with 16px below it and never overlays content.

Accessibility

  • The empty-state title is an h2 in the product (the page's only h1 is the weekday). Illustrations are aria-hidden.
  • The load error uses role="alert" because it replaces content the person was waiting for; the offline notice uses role="status" because it is advisory.
  • Try again keeps focus where it was after it is pressed; while the retry runs, the skeleton returns and "Loading tasks" is announced.
  • State is never colour alone: each alert has an icon and a sentence; "All done" is text plus a tick.
  • Composer stays enabled on load errors (L2-008.6) so the person can still add; the add is attempted on submit.

Content

Empty-state formula: state in a few words + one sentence with the next step. Never blame ("You have no tasks"), never cheerlead with exclamation marks.

Error formula: what happened + what to do: "Couldn't load your tasks. Check your connection and try again." Use "Couldn't", not "Failed to" or "Error:". No apology.

Offline describes the consequence, not the cause: "Changes will fail until you reconnect."
