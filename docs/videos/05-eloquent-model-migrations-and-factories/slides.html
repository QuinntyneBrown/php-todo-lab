The Eloquent model, migrations and factories

An EF Core entity, its configuration and its migrations, mapped onto Todo, create_todos_table and TodoFactory

Active Record versus Data Mapper

EF Core (Data Mapper)

  • Plain entity class
  • Mapping in IEntityTypeConfiguration or OnModelCreating
  • DbContext tracks and saves

Eloquent (Active Record)

  • The model is the entity and the mapper
  • Mapping is traits, properties, and a docblock on the model
  • Todo::query(), $todo->save(), $todo->delete() on the model itself

What you will be able to answer

  1. What each trait and property on Todo does, and its EF Core equivalent
  2. How soft deletes and ULIDs work with no configuration class
  3. Why the model overrides two date methods
  4. How a migration is written by hand, and why it is the only way the schema changes
  5. How factories replace Bogus and test builders

The docblock is the property declaration

/**
 * @property string $id
 * @property string $title
 * @property CarbonImmutable|null $completed_at
 * @property CarbonImmutable $created_at
 * @property CarbonImmutable $updated_at
 * @property CarbonImmutable|null $deleted_at
 * @property-read bool $completed
 */
  • Eloquent reads attributes from an array through magic methods
  • Without the block, Larastan cannot type $todo->title
  • @property-read for the derived completed
  • Review rule: a new column changes this block in the same commit

$dateFormat, $fillable, casts()

backend/app/Models/Todo.php
/** Keeps the millisecond precision of the TIMESTAMP(3) columns. */
protected $dateFormat = 'Y-m-d H:i:s.v';

/** `id` is absent, so a client-supplied id never reaches the row (L2-021). */
protected $fillable = ['title', 'completed_at'];

/**
 * @return array<string, string>
 */
protected function casts(): array
{
    return [
        'completed_at' => 'immutable_datetime',
        'created_at' => 'immutable_datetime',
        'updated_at' => 'immutable_datetime',
        'deleted_at' => 'immutable_datetime',
    ];
}
  • $fillable is the mass-assignment whitelist for create([...]) and update([...])
  • No EF equivalent: EF never binds request arrays to entities. Here the whitelist is the over-posting defence
  • Adding id, or switching to $guarded = [], removes it
  • Casts are HasConversion: timestamps read as CarbonImmutable (L2-045)

Every timestamp is UTC, three layers deep

backend/app/Models/Todo.php
/**
 * Writes every timestamp as UTC, whatever PHP's default timezone is (L2-043).
 */
public function fromDateTime(mixed $value): mixed
{
    return $value === null || $value === ''
        ? $value
        : $this->asDateTime($value)->utc()->format($this->getDateFormat());
}

/**
 * Reads stored timestamps as UTC: the connection runs at +00:00 (config/database.php).
 * Naming the zone also spares Carbon a default-zone lookup on every parse.
 */
protected function asDateTime(mixed $value): Carbon
{
    if (is_string($value)) {
        $parsed = Carbon::createFromFormat($this->getDateFormat(), $value, 'UTC');
        if ($parsed !== null) {
            return $parsed;
        }
    }

    return parent::asDateTime($value);
}
  • config/app.php: 'timezone' => 'UTC'
  • config/database.php: 'timezone' => '+00:00' on the connection
  • The model converts on write and parses as UTC on read
  • UtcTimestampsTest switches PHP to Asia/Tokyo and checks stored and returned values

A derived property and two scopes

backend/app/Models/Todo.php
/**
 * Derived from the stored column, not stored itself (L2-019).
 *
 * @return Attribute<bool, never>
 */
protected function completed(): Attribute
{
    return Attribute::get(fn (): bool => ($this->getAttributes()['completed_at'] ?? null) !== null);
}

/**
 * @param  Builder<Todo>  $query
 */
public function scopeActive(Builder $query): void
{
    $query->whereNull('completed_at');
}
  • $todo->completed: get-only, never stored; a [NotMapped] property. Reads the raw attribute to skip the cast cost.
  • scopeActive → Todo::query()->active(); scopeCompleted mirrors it with whereNotNull. Reusable IQueryable extensions, each tested alone in TodoTest.

The migration

backend/database/migrations/2026_10_08_000000_create_todos_table.php
return new class extends Migration
{
    public function up(): void
    {
        Schema::create('todos', function (Blueprint $table): void {
            $table->charset('utf8mb4');
            $table->collation('utf8mb4_0900_ai_ci');

            $table->ulid('id')->primary();
            $table->string('title', 200);
            $table->timestamp('completed_at', precision: 3)->nullable();
            $table->timestamps(precision: 3);
            $table->softDeletes(precision: 3);

            // Serves the list query: non-deleted, newest first, ties by id (L2-005).
            $table->index(['deleted_at', 'created_at', 'id'], 'todos_deleted_at_created_at_id_index');
            // Serves counts and bulk operations by completion (L2-005, L2-017).
            $table->index(['deleted_at', 'completed_at'], 'todos_deleted_at_completed_at_index');
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('todos');
    }
};
  • Timestamp-prefixed file name orders migrations
  • Anonymous class, up() and down()
  • ulid key, TIMESTAMP(3) columns, two named indexes with the query they serve
  • Resulting schema matches L2-021 column by column

Hand-written, and the only way the schema changes

EF Core

  • Change the entity, run dotnet ef migrations add
  • Generated migration; model snapshot keeps them in sync

Laravel

  • Write the migration and the model separately
  • Nothing enforces agreement except tests and Larastan
  • Upside: the migration is readable and reviewable; the index and its reason are visible
  • Never edit an applied migration; add a new one
$ php artisan migrate            # applies pending migrations, records them in `migrations`
$ php artisan migrate:rollback   # runs down(); TodoTest proves the round trip

Factories: Bogus plus a builder, shipped with the ORM

backend/database/factories/TodoFactory.php
/**
 * @extends Factory<Todo>
 */
class TodoFactory extends Factory
{
    /**
     * @return array<string, mixed>
     */
    public function definition(): array
    {
        return [
            'title' => rtrim(fake()->sentence(4), '.'),
            'completed_at' => null,
        ];
    }

    public function completed(): static
    {
        return $this->state(fn (): array => ['completed_at' => now()]);
    }
}
usage in backend/tests/Feature/Api/V1/ListTodosTest.php
Todo::factory()->count(3)->create();
Todo::factory()->completed()->count(2)->create();
Todo::factory()->create()->delete();
  • definition() is the default row; completed() is a state
  • create([...]) overrides attributes
  • L2-045: factories are the only way tests create data. Raw SQL or DB::table inserts fail review

The seeder

backend/database/seeders/DatabaseSeeder.php
$samples = [
    ['Water the plants', true],
    ['Book a dentist appointment', true],
    ['Call mom', false],
    ['Buy oat milk', false],
    ['Read chapter 3 of the Laravel docs', false],
];

foreach ($samples as $index => [$title, $completed]) {
    $createdAt = now()->subMinutes(count($samples) - $index);

    Todo::factory()->create([
        'title' => $title,
        'completed_at' => $completed ? $createdAt->copy()->addSeconds(30) : null,
        'created_at' => $createdAt,
        'updated_at' => $createdAt,
    ]);
}
  • Same factory, five sample tasks, two completed, staggered created_at
  • php artisan migrate --seed
  • SeederTest checks a handful of rows with both states
  • Array destructuring in foreach: [$title, $completed] is a tuple deconstruction

Pitfalls

  1. id in $fillable, or $guarded = []: mass assignment of the key is open again
  2. Missing class docblock or factory @use: Larastan fails
  3. datetime instead of immutable_datetime
  4. Editing an applied migration instead of adding one
  5. Test data through DB::table or SQL instead of a factory
  6. Expecting a soft delete from a model without SoftDeletes

Things to remember

  • Model: traits for factories, ULIDs and soft deletes; the docblock types the properties; $fillable excludes id; casts are immutable
  • Dates: two overrides pin every timestamp to UTC; completed is derived
  • Scopes: reusable query extensions, tested alone
  • Migration: hand-written, timestamp-ordered, reversible, the only way the schema changes
  • Factories: the only way tests create data
