Table

Tables compare values across rows and columns, with a caption, scoped headers and a scroll wrapper so the page never scrolls sideways.

WCAG 2.2 AAStatus: stableNot used in v1

Overview

A table compares values across rows and columns. In the mocks it documents the screen-reader announcements (notifications); the product itself has no tables in v1.

  • Use a table when people scan down a column or compare across a row. Use a list when each item is read on its own, and a description list for the properties of one thing.
  • Every table has a <caption> (visible or visually hidden) and scope on header cells.
  • Tables scroll horizontally inside .table-wrap; the page itself never scrolls sideways (L2-027.5).

Anatomy

  1. Caption<caption>, --text-h4; names the table.
  2. Header rowUppercase overline on --color-bg-surface-sunken; scope="col".
  3. Body rows12 × 16px cells, 14px text, 1px dividers; hover tint.
  4. Wrapper.table-wrap: 20px radius, --shadow-2, horizontal scroll.

Responsive behaviour

  • Default: the table keeps its columns and scrolls horizontally inside .table-wrap at every width; the page never scrolls sideways (L2-027.5).
  • .table--stack: below MD (48rem) each row becomes a card of label/value pairs; at MD and up it is a normal table.
  • Long text wraps inside cells; numeric columns (.table__num) align right with tabular figures.
  • Row actions stay in the last column and never hide behind hover on touch screens.

Theming

The table reads --color-bg-surface (body), --color-bg-surface-sunken (header), --color-border-default (dividers), --color-bg-subtle (hover), --color-accent-subtle (selected) and --shadow-2 on the wrapper. Dark theme darkens the header below the body surface, matching the sunken well everywhere else.

Accessibility

Role and pattern

A native <table> with <caption>, <thead> and scope. Sortable columns follow the APG Sortable Table example: a button in the header and aria-sort on the sorted column. Not a grid: arrow-key cell navigation is not provided.

Keyboard

KeyAction
TabMoves through sort buttons, row checkboxes and row actions in reading order.
Enter / SpaceSorts by that column (toggling ascending/descending), or activates a row action.
Space on a checkboxSelects the row; the bulk bar's count updates in a polite live region.

Focus

Sort buttons and controls take the shared 2px ring. The scroll wrapper is not focusable unless it scrolls; if it does, give it tabindex="0", role="region" and an aria-labelledby pointing at the caption so keyboard users can scroll it.

Labelling

The caption names the table. Row checkboxes are "Select <first cell>"; the header checkbox is "Select all rows". Row action buttons include the row's name ("Delete row A task is added").

Contrast

Header text on header
Cell text on body
Cell text on hovered row
Cell text on selected row
Checkbox edge on body

Motion

No motion; sorting re-renders in place. Skeleton shimmer stops under reduced motion.

Touch

Checkbox controls and row actions are 44px (small icon buttons are 36px only inside a 48px-tall row); sort buttons meet the 24px minimum with the full header cell around them.

Content

  • Column headers are short nouns in sentence case: "When", "Announced", "How". Uppercase is a style, not the source text.
  • The caption says what the rows are, not "Table".
  • Empty cells show "—" with a visually hidden "None", never a blank.
  • Errors follow the product formula: what happened, then what to do ("Couldn't load the announcements. Check your connection and try again.").
