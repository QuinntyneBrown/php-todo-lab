Checkbox

A checkbox turns one thing on or off. In Tasks the round checkbox is the signature control: ticking it completes a task, draws the tick, bursts a sun-coloured ring once and strikes the title through.

WCAG 2.2 AAStatus: stableUsed in v1Native <input type="checkbox">

Overview

Use a checkbox when a choice is independent of every other choice and takes effect without a separate confirmation step only when the context says so (completing a task does; a form checkbox waits for submit). For one-of-many choices use a radio group; for a setting that applies immediately use a switch.

  • Round (.checkbox--round) is the task check in every row (L2-009, L2-011). It has no visible label: the task title next to it is its accessible name.
  • Square (the default) is the form checkbox, with a visible label and an optional description. Tasks v1 has no form that needs it; it is documented so future settings stay consistent.

Anatomy

  1. Target.checkbox__control: 44 × 44px hit area (--target-comfortable, L2-028.1). The real input stretches over it at zero opacity.
  2. Box.checkbox__box: 24px (--space-6), 2px --color-border-strong ring; square uses --radius-xs, round uses --radius-full.
  3. Tick.checkbox__tick: 14px stroke drawn with stroke-dashoffset, colour --color-fg-on-accent.
  4. Label (square only).checkbox__label, sentence case; optional .checkbox__description beneath in --color-fg-muted.

Variants

Shape follows purpose: round for completing things, square for choosing things. Never mix the two in one list.

Round (task) unchecked and checked; square with label unchecked and checked.

With description

The description is linked with aria-describedby so it is read after the name.

Group

Select all
Related checkboxes sit in a <fieldset> with a <legend>; a parent "select all" shows indeterminate when some children are checked.

Sizes

One size. The box is 24px inside a 44px target so every checkbox meets L2-028.1; a smaller box would need the same target and gains nothing.

States

Hover, focus and press are forced with data-state on the .checkbox label; checked, indeterminate, invalid and disabled use the real attributes. A dash marks a state the round task check never has: a task is done or not, and completing cannot be invalid.

Pending (task row)

A task that was just added and is waiting for the server (L2-004.1) disables its checkbox and dims the whole row to 55% with aria-busy="true" on the row; see task item.

Completion, frame by frame

Checking a round box is the signature moment (L2-011): the circle fills (--duration-base), the tick draws after a 60ms delay, and one sun-coloured ring bursts outwards (.checkbox--burst, --duration-deliberate, 450ms). Script adds .checkbox--burst on check and removes it on animationend; unchecking never bursts.

Both themes

Responsive behaviour

  • The checkbox does not change between breakpoints: 24px box, 44px target at XS through XL.
  • In a task row it occupies the first 44px grid column (--target-comfortable); a 200-character title wraps beside it and the box stays vertically centred on the row (L2-027.6).
  • Square checkbox labels wrap under themselves, never under the box; the label stays clickable across its full width.
  • On touch devices hover never fires, so nothing about the checkbox depends on hover; the hover ring is an enhancement only.

Theming

The checkbox reads --color-border-strong (ring), --color-accent (hover ring and checked fill), --color-fg-on-accent (tick), --color-bg-surface (empty fill), --color-danger-solid (invalid) and --color-highlight (burst). In dark, the accent lightens to sea-400 and the tick flips to sea-950 so the tick still reads at 8.1:1.

Re-skin the box size with the component token --checkbox-size (keep it within the 44px target):

.settings .checkbox__box { --checkbox-size: var(--space-5); }

Accessibility

Role and pattern

A native <input type="checkbox"> (L2-029.2), following the APG Checkbox pattern for free. The visible box is decoration; the input sits over the whole 44px target at opacity: 0, so clicks, screen readers and voice control all hit the real control.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the checkbox. In a task row the order is checkbox, title, delete.
SpaceToggles checked (L2-009.5). Enter does not toggle a checkbox.

Focus

The ring is drawn on the box, not the 44px target: 2px --color-focus-ring with a 2px offset (L2-030.2; the mock's 3px offset was corrected, D16). It appears on :focus-visible only. After a task completes, focus stays on its checkbox; in a filtered view where the row leaves, focus moves to the next row's checkbox.

Labelling

Round: aria-label equal to the task title ("Book dentist appointment"), never "Complete" or "Toggle". Square: the visible .checkbox__label inside the <label>; descriptions via aria-describedby; groups by <fieldset>/<legend>. Completion is announced as "Task completed" / "Task reopened" through the page's polite live region, not by the checkbox.

State never relies on colour alone (L2-030.6): checked adds the tick, and a completed task also strikes its title.

Motion

Fill, tick and burst are opacity, transform and stroke-dashoffset only (L2-024.3). With prefers-reduced-motion the tokens zero every duration: the box is simply checked, no burst plays.

Touch

The target is 44 × 44px at every size (L2-028.1). Nothing is hover-only.

Content

  • Square labels state the thing that becomes true when checked, in sentence case: "Show completed tasks", not "Hide completed tasks: off".
  • No trailing punctuation in labels; descriptions are one sentence with a full stop.
  • Round checkboxes have no visible label; their name is the task title exactly as typed.
  • Never use a checkbox for an action ("Delete"): that is a button.
