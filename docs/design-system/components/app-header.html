App header

The app header tells you what day it is and how much is left. The weekday is the page's only h1; the ring fills as tasks are completed and turns into a tick when everything is done.

WCAG 2.2 AAStatus: stableUsed in v1<header> + <h1>

Overview

The header sits above the task card on the canvas. It has no navigation and no actions: Tasks is one screen (L2-022), so the header is identity and status only. The weekday and date are formatted in the user's locale (L2-022.4); the count is the number of active tasks (L2-007).

It replaces the catalog's generic top bar. There are no search, tabs or menu variants because the product has nothing to navigate to; if a second screen is ever added, use sidebar navigation or tabs under this header rather than adding links to it.

Anatomy

  1. Weekday (h1).app-header__title: --text-display (Bricolage 800, 30→52px fluid), --letter-spacing-tighter. The page's one h1 (L2-029.1).
  2. Date.app-header__subtitle: medium, --color-fg-muted, --space-2 below the weekday.
  3. Count and label.progress-summary__num (--text-stat, tabular) over "left" (--text-label, muted); right-aligned.
  4. Ring.progress-ring: 5-unit track in --color-border-default, accent fill set by --progress (0–1); a tick appears at 1. 48px at XS, 56px from SM.

Sizes

The header is fluid, not sized: the weekday scales with the viewport between 30px and 52px (clamp(var(--font-size-3xl), 8vw, var(--font-size-5xl))) and the ring steps from 48px to 56px at SM. See responsive behaviour.

Responsive behaviour

  • XS: weekday at 30px (8vw clamps to the minimum at 320–375px), ring 48px (L2-027.1); the heading shrinks first and can break mid-word (overflow-wrap: anywhere) before the summary is squeezed.
  • SM and up: ring 56px; the weekday grows with the viewport until it reaches 52px at about 650px.
  • MD, LG, XL: the header spans the 640px column; at LG the whole column is offset 8vh from the top (L2-027.4).
  • Open issue (new drift, found here): at 320–360px, "All done" beside "Wednesday" leaves the weekday about 130px, so the 30px display face breaks the word mid-way (visible in the variants above). The mock has the same geometry with no wrap rule, so there it overflows instead. Proposed fix for the next mock revision: below SM, drop the "All done" text into the visually hidden live announcement and show only the ticked ring.
  • At 200% zoom the summary stays on the same line; "All done" never wraps because the summary is flex: none.

Theming

Weekday and count use --color-fg-default; date and "left" use --color-fg-muted; ring track --color-border-default; ring fill and tick --color-accent. All sit on --color-bg-canvas. Dark swaps the same roles; the accent ring brightens to sea-400 (9.9:1 against the dark canvas).

Accessibility

Role and pattern

A <header> (banner landmark) containing the page's single <h1>, the weekday (L2-029.1). No ARIA widget pattern; see the APG landmark regions guidance.

Keyboard

KeyAction
TabNothing in the header is focusable; Tab goes straight to the composer.
Screen reader heading key (H / 1)Jumps to the weekday.

Focus

No focusable parts; the header never receives focus.

Labelling

The ring is aria-hidden: it repeats the visible count. Count changes are announced through the page's polite live region as "2 left" or "All done" (L2-007.5), not by the header itself, so the number is not read on every render.

Contrast

Weekday and count on canvas
Date and "left" on canvas
Ring fill and tick on canvas

The ring track is decorative (the count is the information); the fill meets 3:1 against the canvas.

Motion

The ring fill animates stroke-dashoffset over --duration-slow; the tick fades and scales in over --duration-base. Nothing animates on load (L2-024.1); reduced motion makes both instant.

Touch

Nothing to tap.

Content

  • Weekday and date come from toLocaleDateString with { weekday: 'long' } and { day: 'numeric', month: 'long' }, so they follow the user's language and order.
  • Count: a bare number over "left" ("3 left"); "All done" replaces both when nothing is left and at least one task exists.
  • No year, no time, no greeting.
