Layer one: an Action around the fake

backend/tests/Unit/Actions/UpdateTodoTest.php
/**
 * Traces to: L2-009, L2-014
 */

declare(strict_types=1);

beforeEach(function (): void {
    $this->repository = new InMemoryTodoRepository;
    $this->action = new UpdateTodo($this->repository);
});

it('completes and reopens a todo', function (): void {
    $todo = $this->repository->seed(title: 'Call mom');

    expect($this->action->handle($todo->id, ['completed' => true])->completed)->toBeTrue()
        ->and($this->action->handle($todo->id, ['completed' => false])->completed_at)->toBeNull();
});

it('keeps completedAt when completing twice', function (): void {
    $todo = $this->repository->seed(title: 'Call mom', completed: true);
    $completedAt = $todo->completed_at;

    expect($this->action->handle($todo->id, ['completed' => true])->completed_at)->toEqual($completedAt);
});

it('throws TodoNotFound for an unknown or deleted id', function (): void {
    $deleted = $this->repository->seed(title: 'Gone', deleted: true);

    expect(fn () => $this->action->handle('01jz0000000000000000000000', ['completed' => true]))
        ->toThrow(TodoNotFound::class)
        ->and(fn () => $this->action->handle($deleted->id, ['completed' => true]))
        ->toThrow(TodoNotFound::class);
});
  • "Traces to" header: the requirement ids, checked in review, never parsed
  • seed(title:, completed:, deleted:): named arguments, a fixed clock advancing one second per row
  • No database, no container, no mocking library: milliseconds
  • L2-051: success, validation and not-found paths through the fake

The fake reads like the contract

backend/tests/Fakes/InMemoryTodoRepository.php
/** A database-free TodoRepository for unit tests of the Actions (L2-044 criterion 3). */
final class InMemoryTodoRepository implements TodoRepository
{
    /** @var array<string, Todo> */
    private array $rows = [];

    private CarbonImmutable $clock;

    /** Adds a todo created one second after the previous one. */
    public function seed(string $title, bool $completed = false, bool $deleted = false): Todo
    {
        $this->clock = $this->clock->addSecond();

        $todo = new Todo;
        $todo->id = Str::lower((string) Str::ulid());
        $todo->title = $title;
        $todo->completed_at = $completed ? $this->clock : null;
        $todo->created_at = $this->clock;
        $todo->updated_at = $this->clock;
        $todo->deleted_at = $deleted ? $this->clock : null;

        return $this->rows[$todo->id] = $todo;
    }

A hand-written fake of a use-case-shaped interface is small, typed, and documents the contract. Moq or NSubstitute would say less.

Layer two: real requests, real MySQL

backend/tests/Feature/Api/V1/CreateTodoTest.php
it('creates a todo and returns 201 with a Location header', function (): void {
    $response = $this->postJson('/api/v1/todos', ['title' => 'Buy oat milk'])
        ->assertCreated()
        ->assertJsonPath('data.title', 'Buy oat milk')
        ->assertJsonPath('data.completed', false)
        ->assertJsonPath('data.completedAt', null);

    $id = $response->json('data.id');
    $response->assertHeader('Location', url("/api/v1/todos/{$id}"));
    expect(Todo::query()->find($id)?->title)->toBe('Buy oat milk');
});

it('rejects a missing, empty, whitespace-only, or non-string title', function (array $body): void {
    $this->postJson('/api/v1/todos', $body)
        ->assertUnprocessable()
        ->assertJsonValidationErrors('title');
})->with([
    'missing' => [[]],
    'empty' => [['title' => '']],
    'whitespace only' => [['title' => '   ']],
    'number' => [['title' => 42]],
    'array' => [['title' => ['x']]],
]);
  • postJson, getJson, patchJson, deleteJson: the whole pipeline in-process, no web server
  • assertCreated, assertJsonPath, assertHeader, assertUnprocessable, assertJsonValidationErrors
  • Then the model, to assert the row
  • One file per endpoint in tests/Feature/Api/V1 (L2-051)

RefreshDatabase, time, and real MySQL

RefreshDatabase

Migrates todo_test once, then wraps each test in a transaction rolled back at the end. Respawn without the deletes; Testcontainers without the container.

Other processes cannot see the rows, hence the committed connection in the concurrency tests.

Time

freezeTime(), travelTo(), travel(5)->minutes() move the clock now() reads. Todos created one second apart; rows aged 25 hours. No sleeping.

Why MySQL, not SQLite

Locking reads, utf8mb4 collation, millisecond timestamps: InnoDB behaviour the backend depends on. L2-051 criterion 1 requires it; CI runs a MySQL 8.4 service.

The coverage gate

backend/composer.json
"test": [
    "@php artisan config:clear --ansi",
    "pest --coverage --min=90 --exclude-group=performance",
    "@php -d pcov.enabled=0 vendor/bin/pest --group=performance"
],
  • Clear the config cache, so phpunit.xml values win
  • 90% minimum over app/Actions and app/Repositories only: where the rules live (L2-051 criterion 3)
  • Controllers and Resources are exercised by the feature tests anyway; a gate on glue rewards the wrong tests
  • The performance group runs with pcov off so timings are fair

One slice, in order

  1. Write the Given-When-Then acceptance criteria
  2. Write the acceptance test with its Traces to: L2-xxx header
  3. Run it: it must fail for the expected reason (a 404 before the route exists, an assertion in an Action test)
  4. Write only the production code that makes it pass
  5. Refactor with the tests green; run the relevant checks
  6. Only then start the next slice

Never write architecture tests

No test asserts the folder layout, class naming, banned APIs, or that every file has a traces header. Those belong to Larastan, Pint, and review.AGENTS.md, "Never write architecture tests". The suite proves behaviour only.

Pitfalls

  1. SQLite for tests: the suite depends on MySQL semantics, and L2-051 forbids it
  2. Rows through DB::table or SQL instead of factories
  3. Mockery for the repository when the fake exists
  4. Asserting the shape of the code instead of its behaviour
  5. Missing "Traces to" header
  6. A test written after the implementation: the failing run is the evidence

Things to remember

  • Pest: it, expect, with, throws, beforeEach, helper functions, over PHPUnit
  • Unit: an Action around InMemoryTodoRepository, no database
  • Feature: real requests through the pipeline against MySQL; RefreshDatabase, factories, time travel
  • Gate: 90% on Actions and repositories; performance group without instrumentation
  • Workflow: a failing acceptance test first; no structure tests
