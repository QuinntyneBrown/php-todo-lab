Responsive

One centred column from 320px to 1920px. Phones are the base; wider screens add room, never different features.

WCAG 2.2 AAL2-027L2-028

Overview

Tasks is one centred column on every screen (L2-027). It is designed mobile first: the base styles are the 320–575px layout, and min-width queries add room as the viewport grows. The mocks wrote phone rules as max-width: 575.98px overrides; the system turns them around (D18).

NameRangeQueryTask column
XS320–575px(base)Full width, 16px side gutters, ring 48px, filter full width, Add task icon only
SM≥ 576px@media (min-width: 36rem)Up to 560px, centred; counts and the Add task label appear; ring 56px
MD≥ 768px@media (min-width: 48rem)640px, top offset 40px, list on a raised rounded card
LG≥ 992px@media (min-width: 62rem)Stays 640px, offset 8vh from the top; never stretches
XL≥ 1200px@media (min-width: 75rem)Same as LG

Queries are written in rem so they move with the user's font size. Custom properties cannot be used inside @media, so the values repeat the --layout-breakpoint-* tokens by convention (see layout).

Mobile-first rules

  • Write the XS style first, then add. A rule that only exists to undo a wider layout is a sign the base is wrong.
  • Prefer tokens that change at a breakpoint (--layout-container-max, --layout-offset-top) over component media queries.
  • Nothing scrolls sideways from 320px to 1920px (L2-027.5). Tables are the only content allowed to scroll inside their own wrapper.
  • Text wraps, it never truncates: a 200-character title wraps onto as many lines as it needs and the row grows; the checkbox and delete stay aligned (L2-027.6).
  • Type does not scale with viewport width, except the display date (clamp(1.875rem, 8vw, 3.25rem)). Spacing never does.
The task card at 360px: icon-only Add task, full-width filter without counts, Clear completed on its own line, a long title wrapping.

Touch and pointer

  • 44 × 44px targets for every product control (L2-028.1): --target-comfortable. The checkbox draws a 24px circle inside a 44px hit area; delete is a 44px circle.
  • No hover-only actions on touch: @media (hover: hover) hides delete until the row is hovered or focused; on hover: none devices it is always visible (L2-028.2). Focus-within reveals it for keyboards on every device.
  • Inputs ≥ 16px so iOS does not zoom on focus (L2-028.3). Text inputs use --font-size-lg (18px).
  • Safe areas: the toast region sits calc(16px + env(safe-area-inset-bottom)) from the bottom and the page keeps --layout-safe-bottom clear beneath the list so the toast never covers the last row (L2-028.5). The viewport meta includes viewport-fit=cover.
  • Orientation: nothing is locked; rotating keeps the composer text and any edit in progress (L2-028.4).
  • 100dvh for full-height layouts so mobile browser chrome does not clip.
  • pointer: coarse is not used to enlarge controls; they are already 44px.

Tokens

Responsive behaviour uses the layout tokens (--layout-breakpoint-*, --layout-container-max, --layout-offset-top, --layout-safe-bottom) documented on the layout page, and the target-size tokens on the accessibility page.
