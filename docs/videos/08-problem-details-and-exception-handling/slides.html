Problem details and exception handling

IExceptionHandler and ProblemDetails, mapped onto ProblemDetailsRenderer and the domain exceptions

What the defaults would do

ASP.NET Core

  • [ApiController]: 400 ValidationProblemDetails for free
  • AddProblemDetails() + UseExceptionHandler()
  • Custom mapping in an IExceptionHandler

Laravel, out of the box

  • Validation: Laravel's own JSON shape (message + errors)
  • Unknown route: an HTML page unless the client asks for JSON
  • Crash: an HTML error page

One class, ProblemDetailsRenderer, replaces all three with RFC 9457 (L2-020).

What you will be able to answer

  1. Where exception rendering is registered, versus IExceptionHandler
  2. How every error class maps to status, title, detail, and extensions
  3. Why the renderer checks the request path, not the Accept header
  4. How a 500 avoids leaking internals
  5. How the tests prove it without a running server

The arms, in order

backend/app/Exceptions/ProblemDetailsRenderer.php
return match (true) {
    $e instanceof ValidationException => self::problem(422, 'One or more fields are invalid.', [
        'errors' => $e->errors(),
    ]),
    $e instanceof TodoLimitReached => self::problem(422, $e->getMessage(), [
        'code' => 'todo_limit_reached',
        'errors' => ['title' => [$e->getMessage()]],
    ]),
    $e instanceof TodoNotFound, $e instanceof ModelNotFoundException => self::problem(404, 'The requested resource was not found.'),
    $e instanceof MethodNotAllowedHttpException => self::problem(
        405,
        "The {$request->method()} method is not supported for this route.",
        headers: $e->getHeaders(),
    ),
    $e instanceof HttpExceptionInterface && $e->getStatusCode() === 404 => self::problem(404, 'The requested resource was not found.'),
    $e instanceof HttpExceptionInterface => self::problem($e->getStatusCode(), $e->getMessage(), headers: $e->getHeaders()),
    default => self::problem(500, 'An unexpected error occurred. Try again later.'),
};

The body: four members plus extensions

backend/app/Exceptions/ProblemDetailsRenderer.php
private static function problem(int $status, string $detail, array $extensions = [], array $headers = []): JsonResponse
{
    return new JsonResponse(
        [
            'type' => 'about:blank',
            'title' => Response::$statusTexts[$status] ?? 'Error',
            'status' => $status,
            'detail' => $detail,
            ...$extensions,
        ],
        $status,
        ['Content-Type' => 'application/problem+json', ...$headers],
    );
}

Every status has a test

backend/tests/Feature/Api/V1/ProblemDetailsTest.php
function assertProblem(Illuminate\Testing\TestResponse $response, int $status, string $title, string $detail): void
{
    $response->assertStatus($status)
        ->assertHeader('Content-Type', 'application/problem+json')
        ->assertJsonPath('type', 'about:blank')
        ->assertJsonPath('title', $title)
        ->assertJsonPath('status', $status)
        ->assertJsonPath('detail', $detail);
}

it('renders unhandled exceptions as 500 problem details without leaking the message', function (): void {
    Route::get('api/v1/boom', fn () => throw new RuntimeException('secret internals'));

    $response = $this->get('/api/v1/boom', ['Accept' => 'text/html']);

    assertProblem($response, 500, 'Internal Server Error', 'An unexpected error occurred. Try again later.');
    expect($response->getContent())->not->toContain('secret internals');
});
  • Full pipeline in-process: router, middleware, renderer. WebApplicationFactory without the factory
  • A throwaway route that throws proves the 500 never echoes internals
  • 405 test checks the Allow header contains GET
  • TodoLimitTest pins code and the exact sentence
  • Every error-path test in the suite asserts application/problem+json

Pitfalls

  1. Hand-built JSON errors in a controller or Action: a second error shape
  2. expectsJson() or the Accept header instead of the path: a browser gets HTML
  3. The generic HttpExceptionInterface arm before the specific 404 and 405 arms
  4. A 500 that echoes getMessage()
  5. A new domain exception with no arm and no test: a meaningful failure becomes a generic 500

Things to remember

  • Registration: one invokable renderer in bootstrap/app.php; reporting stays with Laravel
  • Scope: by path, so the API never returns HTML
  • Mapping: match (true): 422 + errors, 422 + code, fixed 404, 405 + Allow, fixed 500
  • Body: four RFC 9457 members plus extensions, application/problem+json
  • Tests: every status pinned in-process
