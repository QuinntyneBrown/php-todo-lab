Pattern

Dialogs and overlays

v1 has none by design. Undo replaces confirmation; in-place editing replaces forms in boxes.

Overview

Tasks v1 has no dialogs, drawers or popovers. L2-022.2 requires that the page contains exactly its five regions and no modal dialogs, and every flow is designed around that: destructive actions are undone from a toast instead of confirmed, titles are edited in place, and errors appear where they happened.

This page records why, and sets the rules for when a later version may introduce an overlay. The components exist and are documented: Dialog, Tooltip, Menu.

When to use

Needv1 answerIf a future version needs an overlay
Confirm a destructive actionAct, then offer Undo for 6 s (L2-015, L2-017)Dialog only when the action cannot be undone (for example deleting an account)
Edit a recordInline edit in the row (L2-012)Dialog with a form when it has several fields and the list must stay visible behind it
Show more actions for a rowOnly delete exists; it is a visible icon buttonMenu behind a "More actions for title" button
Explain an icon-only controlEvery icon button has an aria-label; the icons are conventional (plus, bin)Tooltip on hover and focus, never containing actions
Settings, help, aboutNone exist (L2-022)A page or drawer, not a dialog stacked over the list

Decision order: prefer in place, then undo, then a page; use a dialog only when the person must decide before anything happens. Never stack one overlay on another.

A future, irreversible confirmation (not in v1) and a tooltip on an icon button. Both are shown statically.
  1. Backdrop: --color-bg-backdrop; the page behind is inert.
  2. Header: optional danger icon, title as the accessible name, close button.
  3. Body: what will happen and whether it can be undone.
  4. Footer: the safe action first, the committing action last; labels name the consequence ("Delete 12 tasks").

Responsive behaviour

  • Below SM (576px) a dialog is a bottom sheet: full width, top corners rounded, footer sticky, at most 90dvh tall; above SM it is centred at 32rem (24rem small, 44rem large).
  • Tooltips flip below their anchor (.tooltip--below) when there is no room above, and wrap at 16rem.
  • Touch has no hover: anything a tooltip says must also be in the control's accessible name or visible text.

Accessibility

  • Dialogs follow the APG modal dialog pattern: native <dialog> opened with showModal(), labelled by its title, described by its body, focus trapped, Esc closes, focus returns to the trigger.
  • Tooltips follow the APG tooltip pattern: role="tooltip" referenced by aria-describedby, shown on hover and focus, dismissible with Esc (WCAG 1.4.13).
  • Toasts are not overlays in this sense: they never take focus and never block the page.

Content

  • Title is the question with its object and number: "Delete all 12 tasks?" Not "Are you sure?"
  • Body says the consequence and whether it can be undone. One or two sentences.
  • Buttons name outcomes: "Keep tasks" / "Delete 12 tasks". Never "OK" / "Cancel" for destructive choices.
  • Tooltips repeat the accessible name, in sentence case, without a full stop.
