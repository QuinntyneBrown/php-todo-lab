Switch

A switch turns a setting on or off the moment it is flipped, like a light switch. It never waits for a Save button.

WCAG 2.2 AAStatus: stableNot used in v1<input type="checkbox" role="switch">

Overview

Use a switch for a single setting that takes effect immediately and can be flipped back without consequence. Use a checkbox when the choice waits for a form submit, and a radio group when there are more than two states.

Not used in v1. Tasks has no settings: the theme follows the operating system with no toggle (L2-026) and the one screen has no preferences (L2-022). The switch is documented so the first setting added later uses the system's ring, accent and target sizes.

Anatomy

  1. Target.switch__control: 44px tall; the native input covers it.
  2. Track.switch__track: 44 × 24px pill, --color-border-strong off, --color-accent on.
  3. Thumb20px circle in --color-bg-surface with --shadow-1; slides over --duration-base.
  4. LabelNames the setting, not the action.

Variants

Label right (default), label left (.switch--label-start, the label leads in a settings list), with description.
HTML
<label class="switch">
  <span class="switch__control">
    <input class="switch__input" type="checkbox" role="switch" checked>
    <span class="switch__track"></span>
  </span>
  <span>Move completed tasks to the bottom</span>
</label>

Sizes

One size: the 44 × 24px track already fills the 44px target height the product requires (L2-028.1).

States

ValueDefaultHoverFocusDisabled
Off
On

A switch has no invalid state: it cannot be wrong. If flipping it fails to save, revert it and say so in a toast ("Couldn't save that change."), the same way a failed task toggle reverts (L2-010.2).

Both themes

Responsive behaviour

  • The switch is the same size at every breakpoint.
  • In a settings list at XS, use .switch--label-start with the row at full width so the label reads first and the track sits at the line start; labels wrap beneath themselves.
  • Never put two switches on one line below MD.

Theming

Track off: --color-border-strong; track on: --color-accent; thumb: --color-bg-surface with --shadow-1; hover halo: --color-bg-subtle-hover. In dark the accent lightens and the thumb stays the dark surface, so the on state reads as a bright track with a dark knob.

Accessibility

Role and pattern

A native checkbox with role="switch", the APG Switch pattern. Screen readers announce "on/off" instead of "checked/not checked".

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the switch.
SpaceFlips it; the setting applies immediately.

Focus

The shared ring wraps the track with a 2px offset.

Labelling

The label describes the setting ("Move completed tasks to the bottom"), so "on" makes sense after it. Never "Enable" or "Turn on …". Descriptions via aria-describedby.

Contrast

Off track on card
On track on card
Focus ring

On and off also differ by thumb position, so state never relies on colour alone.

Motion

The thumb slides with a transform over --duration-base; reduced motion makes it jump.

Touch

The whole label row is the target, at least 44px tall.

Content

  • Label the state that "on" produces, as a noun or verb phrase in sentence case: "Play the completion burst".
  • Never show "On"/"Off" text next to the switch; the position and announcement already say it.
  • If the change has a consequence, describe it in the description, not in a confirmation.
