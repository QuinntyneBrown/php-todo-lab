Form layout

Form layout arranges fields, fieldsets and actions into a form people can complete top to bottom. One column, labels above, the primary action last.

WCAG 2.2 AAStatus: stableNot used in v1<form novalidate> + <fieldset>

Overview

.form stacks form fields with --space-6 between them and caps the width at --layout-measure. Use it for any form with more than one field. A single field and its button is an inline form (.form--inline), which is what the composer specialises.

Not used in v1 beyond the composer. L2-022 keeps Tasks to one screen and its only form is the one-field composer. This page fixes the rules for any future multi-field form so it matches the composer's validation behaviour: novalidate, messages under the field, nothing lost on failure.

Anatomy

  1. Fieldset and legend.fieldset groups related fields; .fieldset__legend is an h4-sized title.
  2. Fields.field blocks, --space-4 apart inside a fieldset, --space-6 between groups.
  3. Actions bar.form__actions: right-aligned, primary last, --space-3 gap; wraps on narrow screens.

Inline

.form--inline: one field and its action on a line; the button aligns with the input's bottom edge.

Sizes

Forms take their size from their fields and the measure; there is no form-level size.

States

FormDefaultInvalidSubmitting
Inline

Enter a list name.
  • Invalid: client validation runs on submit (and re-runs on input once a field has an error); messages appear under each field; nothing typed is cleared.
  • Submitting: the form gets aria-busy="true", the pressed button shows its spinner (aria-busy), fields become read-only. Prefer optimistic updates where the product allows, as the composer does (L2-004).
  • Failed: field errors from the server (422) go under their fields as sent; anything else becomes an error toast and the form keeps its values.

Responsive behaviour

  • XS and SM: one column; .form__row--split stacks.
  • MD and up (48rem): split rows become two equal columns, only for short related fields (start/due date).
  • The actions bar wraps; when wrapped, the primary action stays last. Below MD a form's single primary action may use .btn--block.
  • Inline forms wrap the button under the field when the line is narrower than about 12rem plus the button.

Theming

The form adds no colour of its own: fields, alerts and buttons carry their tokens. The only form-level tokens are spacing (--space-6 between fields, --space-4 inside a fieldset, --space-3 between actions) and the width cap --layout-measure.

Accessibility

Role and pattern

A native <form> (give it aria-label when a page has more than one), <fieldset>/<legend> for groups, and an error summary that follows the WAI form notifications guidance. novalidate replaces browser bubbles with the system's messages.

Keyboard

KeyAction
TabMoves through fields in visual order, then the actions (Cancel before the primary).
Enter in a text fieldSubmits the form.
EscNo effect on a page form; it cancels only in-place edits such as a task title (L2-012).

Focus

On a failed submit focus moves to the error summary (two or more errors) or to the single invalid field. After a successful inline submit focus stays in the field, as in the composer (L2-001.3).

Labelling

Every field labelled; required fields say "(required)"; the error summary is a role="alert" region whose title counts the errors and whose links name each problem.

Motion

Forms do not animate; only the composer shakes its field once on an empty submit (and not with reduced motion).

Touch

Fields and buttons are 44px; actions are --space-3 apart.

Content

  • The primary action names the result: "Save task", "Create list". Never "Submit" or "OK".
  • Summary title counts and instructs: "Fix 2 fields to save this task".
  • Each summary link repeats the field's message word for word.
  • No apologies, no exclamation marks (L2-025).
