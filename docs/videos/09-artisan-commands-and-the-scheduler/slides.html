Artisan commands and the scheduler

Hosted services and background jobs, mapped onto PurgeDeletedTodos and routes/console.php

No long-lived process

.NET

  • BackgroundService + PeriodicTimer inside the web process
  • Quartz, Hangfire: a scheduler that stays alive

Laravel

  • A command class: todos:purge-deleted
  • A schedule declared in code: routes/console.php
  • System cron runs php artisan schedule:run every minute

What you will be able to answer

  1. How an Artisan command is declared and receives dependencies
  2. How the purge deletes in chunks, and why
  3. How the scheduler runs without a long-lived process, and what production needs
  4. How commands and schedules are tested, including time travel

The command class

backend/app/Console/Commands/PurgeDeletedTodos.php
/** Permanently removes todos soft-deleted more than 24 hours ago (L2-016). */
final class PurgeDeletedTodos extends Command
{
    public const int RETENTION_HOURS = 24;

    /** Small chunks keep each DELETE short, so it never holds long locks. */
    public const int CHUNK_SIZE = 500;

    protected $signature = 'todos:purge-deleted';

    protected $description = 'Permanently delete todos soft-deleted more than 24 hours ago';

    public function handle(TodoRepository $todos): int
    {
        $cutoff = now()->toImmutable()->subHours(self::RETENTION_HOURS);
        $purged = 0;

        do {
            $chunk = $todos->purgeDeletedBefore($cutoff, self::CHUNK_SIZE);
            $purged += $chunk;
        } while ($chunk === self::CHUNK_SIZE);

        $message = "Purged {$purged} soft-deleted todos.";
        Log::info($message);
        $this->info($message);

        return self::SUCCESS;
    }
}
  • Discovered automatically from app/Console/Commands; php artisan list shows it
  • $signature: the name you type; $description: the help text
  • handle(TodoRepository $todos): method injection, the interface, never Eloquent
  • Returns an exit code: self::SUCCESS is 0, self::FAILURE is 1

  • Cutoff as an immutable date, now minus 24 hours

Why chunks of 500

do {
    $chunk = $todos->purgeDeletedBefore($cutoff, self::CHUNK_SIZE);
    $purged += $chunk;
} while ($chunk === self::CHUNK_SIZE);
backend/app/Repositories/EloquentTodoRepository.php
public function purgeDeletedBefore(CarbonImmutable $cutoff, int $limit): int
{
    return Todo::onlyTrashed()
        ->where('deleted_at', '<', $cutoff)
        ->limit($limit)
        ->forceDelete();
}
  • One DELETE over thousands of rows holds row locks for the whole statement and can block the live API
  • 500 at a time keeps every statement short (L2-016 criterion 4)
  • A short batch means the last one is done
  • Policy (how many, how old) in the command; SQL in the repository

The schedule is one line of code

backend/routes/console.php
<?php

declare(strict_types=1);

use Illuminate\Support\Facades\Schedule;

Schedule::command('todos:purge-deleted')->hourly();
  • Versioned, reviewed, testable: the test asserts the expression is 0 * * * *
  • Runs in the application time zone, which config/app.php fixes to UTC
  • Registered through withRouting(commands: ...) in bootstrap/app.php

How it fires: cron is the timer

system cron, every minute
→
php artisan schedule:run
→
boot, evaluate every expression
→
todos:purge-deleted if due
→
exit
# production crontab: one line
* * * * * cd /path/to/backend && php artisan schedule:run >> /dev/null 2>&1

# local development
$ php artisan schedule:work          # foreground loop that ticks every minute
$ php artisan todos:purge-deleted    # run it once, now
Purged 0 soft-deleted todos.

Stateless between ticks: the shared-nothing model applied to background work.

Time travel in tests

backend/tests/Feature/Console/PurgeDeletedTodosTest.php
function deletedHoursAgo(int $hours, int $count = 1): void
{
    test()->travelTo(now()->subHours($hours));
    Todo::factory()->count($count)->create()->each->delete();
    test()->travelBack();
}

it('purges todos soft-deleted more than 24 hours ago and keeps the rest', function (): void {
    $this->freezeTime();
    deletedHoursAgo(25);
    deletedHoursAgo(24);
    deletedHoursAgo(23);
    $live = Todo::factory()->create();

    $this->artisan('todos:purge-deleted')->assertSuccessful();

    expect(Todo::withTrashed()->count())->toBe(3)
        ->and(Todo::query()->pluck('id')->all())->toBe([$live->id]);
});
  • now() reads a clock tests can move: travelTo, travel, freezeTime
  • No injection needed: the command already calls now()
  • 25 h purged, 24 h kept, 23 h kept: the boundary is strictly older than a day
  • $this->artisan(...) runs the command in-process

Output, chunks, and the schedule

backend/tests/Feature/Console/PurgeDeletedTodosTest.php
it('exits successfully and logs zero when nothing is eligible', function (): void {
    Log::spy();
    deletedHoursAgo(1);

    $this->artisan('todos:purge-deleted')
        ->expectsOutput('Purged 0 soft-deleted todos.')
        ->assertExitCode(0);

    Log::shouldHaveReceived('info')->with('Purged 0 soft-deleted todos.')->once();
});

it('purges more rows than fit in one chunk', function (): void {
    deletedHoursAgo(48, 1201);

    $this->artisan('todos:purge-deleted')
        ->expectsOutput('Purged 1201 soft-deleted todos.')
        ->assertSuccessful();

    expect(Todo::withTrashed()->count())->toBe(0);
});

it('is scheduled to run hourly', function (): void {
    $events = collect(app(Schedule::class)->events())
        ->filter(fn ($event): bool => str_contains((string) $event->command, 'todos:purge-deleted'));

    expect($events)->toHaveCount(1)
        ->and($events->first()->expression)->toBe('0 * * * *');
});

What these tests are not

Not

  • Unit tests with a mocked repository
  • Running the scheduler with real time

Instead

  • Against MySQL through the real repository: the behaviour is "rows older than a day are gone"
  • Reading the declared schedule from the container: milliseconds, no flake

Pitfalls

  1. DB or Todo::query in the command: layering broken, chunk contract skipped
  2. One big DELETE: long locks
  3. handle() returning nothing: failures exit 0; return self::FAILURE
  4. No cron line in production: schedule:work locally hides it
  5. Schedule tests that execute through the scheduler with real time

Things to remember

  • Command: signature, description, handle() with method injection, an exit code
  • Purge: cutoff, loop in chunks of 500 through the repository, one log line
  • Schedule: one line of code; cron runs schedule:run every minute; nothing stays alive
  • Tests: travelTo, freezeTime, $this->artisan, Log::spy, read the schedule
