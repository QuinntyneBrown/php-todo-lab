Pattern

Content and tone

One name for each thing, one verb for each action, and no apologies.

WCAG 2.2 AAUsed in v1L2-025, L2-031

  • When to use
  • Structure

Overview

Copy is plain, active, sentence case, and uses one name for each thing: "task" in the UI, "Add task", "Undo", "Clear completed". Errors say what happened and what to do and never apologise (L2-025). Every string lives in one typed constants file (UI_STRINGS in the frontend) so it can be reviewed and later localised.

The rules in full are on the Content foundation; this page shows them applied across a screen and collects the microcopy library.

Responsive behaviour

  • Labels are short enough not to wrap at 360px; the only label that hides at XS is "Add task", which stays as the button's aria-label.
  • Filter counts are hidden below SM but remain in the accessible names.
  • Dates use the user's locale and the long weekday ("Wednesday"); never abbreviate to fit.

Accessibility

  • Visible label and accessible name match, or the name starts with the visible label (WCAG 2.5.3): "Delete Call mom".
  • Error messages name the fix (WCAG 3.3.3); announcements reuse the visible verb, so screen-reader and sighted users learn the same words.
  • <html lang="en">; dates and numbers come from Intl with the user's locale.

Content

  • Voice: calm, brief, helpful; second person only when needed ("You're offline").
  • Casing: sentence case everywhere, including buttons and toasts.
  • Punctuation: full stops on sentences (errors, empty-state text); none on labels, buttons and toasts that are fragments. Straight apostrophes in code, typographic in UI.
  • Numbers: digits ("3 tasks"), singular for one ("1 task cleared").
  • Never: "Oops", "Sorry", "Please", "Error:", exclamation marks, "item" or "todo" instead of "task".
