Menu

A menu gathers several related actions behind one button, so a dense surface stays calm. It opens on demand and closes as soon as an item is chosen.

WCAG 2.2 AAStatus: readyNot used in v1APG Menu Button

Overview

Use a menu when one trigger offers three or more actions that do not each deserve a visible button: "Sort", "Export", "Delete completed". Use a segmented control for views, a select to pick a value inside a form, and a visible button when there are only one or two actions.

Not used in v1. The product has exactly four actions (add, complete, edit, delete) plus Clear completed and Undo, and every one is visible (L2-022: one screen, nothing hidden). The menu is ready for later features such as sorting or a per-task "more" menu; it is built only from existing tokens (D22).

Anatomy

  1. TriggerA .btn with aria-haspopup="menu" and aria-expanded; chevron icon.
  2. Section label.menu__section: overline, presentation only.
  3. Item.menu__item: 44px tall, optional leading icon or check mark.
  4. Shortcut.menu__shortcut: caption, --color-fg-subtle, right-aligned.

Variants

  • Show
With icons, shortcuts, a separator and a danger item; with a section and checkable items (menuitemcheckbox).

Sizes

Menus have one size: 44px items, 12–20rem wide.

Responsive behaviour

  • The menu opens below its trigger, aligned to its start edge; near the right or bottom edge it flips to stay inside the viewport (script measures and sets right: 0 or bottom: 100%).
  • Width is 12–20rem; at XS it never exceeds the viewport minus the 16px gutters.
  • Items stay 44px tall at every size; no hover-only actions.

Theming

The panel uses --color-bg-surface-raised, --shadow-3 and a hairline --color-border-default edge, so in dark it reads lighter than the card it opens over. Items read --color-bg-subtle on hover; danger items read --color-danger-fg on --color-danger-bg.

Accessibility

Role and pattern

APG Menu Button: the trigger has aria-haspopup="menu", aria-expanded and aria-controls; the list is role="menu" with menuitem, menuitemcheckbox or menuitemradio children (roving tabindex).

Keyboard

KeyAction
Enter, Space, ↓On the trigger: opens and focuses the first item. ↑ opens on the last.
↓ / ↑Moves between items, wrapping; disabled items are focusable but inert.

Letter keysType-ahead to the next item starting with that letter.

EscCloses and returns focus to the trigger.
TabCloses and moves on in page order.

Focus

Focus moves into the menu on open and back to the trigger on close. The focused item gets the hover fill plus an inset 2px ring, so the ring is never clipped by the panel.

Labelling

The trigger's text names the menu; the menu takes aria-labelledby pointing at the trigger. Checked state comes from aria-checked; the check icon is decorative.

Motion

None on open; the menu appears in place. Reduced motion needs no change.

Touch

44px items; tapping outside closes the menu without activating anything.

Content

  • Items are verb phrases in sentence case: "Edit title", "Delete task". Checkable items name the setting: "Completed tasks".
  • Put the destructive item last, after a separator.
  • Name the trigger after what the menu does ("Sort"), or "More actions for Call mom" when icon-only.
