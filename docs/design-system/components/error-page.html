Error page

A full-screen message for when the app cannot show anything: unknown address, server failure or no connection.

WCAG 2.2 AAStatus: stableNot used in v1

Overview

An error page replaces the whole screen when the app cannot show anything useful: the address does not exist, the app failed to start, or it cannot load at all. v1 does not use one: there is a single route (/), the shell renders without the API, and every failure is handled in place with the banner, the offline notice or an error toast (L2-008.5, L2-042). The page is in the core set for future routes (D22).

  • Prefer keeping the shell and showing an inline alert. Use an error page only when there is no shell to keep.
  • One way to recover, always.

Anatomy

  1. CodeOverline in --color-fg-accent: 404, 500 or "Offline".
  2. Illustration88px, drawn with the empty-state art palette.
  3. Title--text-h1; the page's only h1 in production.
  4. TextWhat happened and what to do, muted, 40ch.
  5. ActionOne primary button or link that recovers.
  6. Reference500 only: a monospace id to quote to support.

Responsive behaviour

  • Single centred column at every width; text capped at 40ch, title balanced.
  • 64px block padding from SM; at XS the content starts 64px from the top so the action stays above the fold at 320 × 568.
  • Actions wrap and centre; on phones the primary action stays one tap from the thumb, never pinned.

Theming

No component tokens. Code --color-fg-accent, title --color-fg-default, text --color-fg-muted, reference --color-fg-subtle; illustrations use the art classes from Empty state, with .art-line--danger for the failure mark.

Accessibility

Role and pattern

A full page: <title> starts with the problem ("Page not found — Tasks"), one h1, a main landmark, and the action as a real link or button. No ARIA pattern needed. (On this documentation page the titles are h2 because the page already has its h1.)

Keyboard

KeyAction
TabSkip link, then the recovery action.
EnterFollows the link or activates Try again.

Focus

On load, focus starts at the top of the document as usual; the title is the first thing read after the page title.

Labelling

The code (404) is visible text but the title carries the meaning; screen readers hear "404, Page not found".

Content

  • Title says what is wrong in plain words: "Page not found", "You're offline". Not "Error 404".
  • Text: cause, then the next step. "Something failed on the server. Try again in a moment."
  • Never apologise or blame the person; no "Oops" (L2-025).
  • Action labels: "Go to your tasks", "Try again".
