Foundation · Motion

Motion

Five durations and four easings. Motion confirms an action or shows what changed, and disappears entirely when someone asks for less.

WCAG 2.2 AAL2-0249 tokens
  • Overview
  • Durations
  • Easings
  • Completion choreography
  • Usage
  • Reduced motion
  • Tokens

Overview

Motion in Tasks exists only to confirm an action or show what changed (L2-024). Nothing animates on page load except the skeleton shimmer, every curve eases out, and every animation changes only transform, opacity, background-size or stroke-dashoffset, never layout on a frame loop.

The mocks used twelve different durations between 60 ms and 1.4 s (drift D15). They collapse into five duration tokens and four easings. Under prefers-reduced-motion: reduce the tokens themselves drop to 0.01 ms, so components need no media queries of their own (D21).

Easings

All four curves over the same 450 ms so the shape is visible. Standard and enter are the product curve cubic-bezier(0.22, 1, 0.36, 1) from the mocks' --ease-out.

--ease-enter over --duration-deliberate
--ease-exit over --duration-deliberate

--ease-exitElements leaving for good (toast out). Accelerates away. System addition (D22).
--ease-springOvershoot for playful confirmations. Not used in v1; reserved. System addition (D22).

Completion choreography

Completing a task is the signature moment. Three things happen inside 500 ms, staggered so they read as one gesture:

  1. Fill and tick: the circle fills with --color-accent over --duration-base; the tick draws itself (stroke-dashoffset) starting 0.3 × --duration-base (60 ms) later.
  2. Burst: one --color-highlight ring scales from 1 to 2.1 and fades over --duration-deliberate (450 ms). Added by script as .checkbox--burst for one cycle.
  3. Strike: the title's strike-through wipes left to right (background-size) over --duration-slow while the text fades to --color-fg-muted.

Usage

  • Pick the duration by what changed, not by taste: colour → fast, state → base, arrival or departure → slow, celebration → deliberate.
  • Animate transform and opacity. Never animate height, width or top on a loop.
  • Write transition: color var(--duration-fast) var(--ease-standard); never a raw .15s. Multiples are expressed with calc() on a token so they still collapse under reduced motion.
  • One thing moves at a time per gesture, except the completion sequence, which is choreographed.
  • Nothing animates on load; content renders in place.

Reduced motion

tokens.css sets --duration-fast, --duration-base, --duration-slow and --duration-deliberate to 0.01ms under prefers-reduced-motion: reduce. Transitions and one-shot animations therefore finish instantly: the checkbox still ends checked with its tick, the strike still appears, rows still leave; only the movement disappears (L2-024.2, WCAG 2.3.3).

Looping indicators would flicker at 0.01 ms, so components.css stops them explicitly: the skeleton shimmer becomes a static tone, the spinner a still partial ring, the indeterminate progress bar a half-opacity full bar, and the composer shake is removed. This replaces the mocks' blanket * { animation-duration: .001ms !important } override (D21).

Status never relies on motion: every animated change also has an end state (checked box, strike, toast text) and a live-region announcement.
