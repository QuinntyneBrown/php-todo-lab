Badge

A small static label for a status, a category or a count.

Overview

A badge is a small, non-interactive label for a status, a category or a count. In the mocks it is the requirement tag (.tag) beside every specimen title; in the system it also carries status tones.

  • Use a badge to label something; use a chip when people can press it, and an alert for a message.
  • The product's filter counts use .segmented__count, not badges, to keep the control quiet.

Anatomy

  1. Dot (optional)8px circle in the text colour; reinforces a status.
  2. Label12px semibold, 2 × 8px padding, full radius.

Sizes

Badges have one size (12px text); they scale with the user's font size.

States

Badges are static: no hover, focus, active or disabled states. They change only when their content changes, and a changing count is announced through a live region, not the badge.

Responsive behaviour

  • Badges never wrap internally (white-space: nowrap); keep labels to one or two words so they fit at 320px.
  • In a heading they wrap to the next line with the text around them.

Theming

Two component tokens, --badge-bg and --badge-fg, set from the status tokens (--color-*-bg/-fg, or -solid with --color-fg-inverse). In dark the subtle tones become deep tints with light text, and solid badges flip to light fills with dark text.

Accessibility

Role and pattern

Plain inline text in a <span>; no role. A count badge has an aria-label with its meaning. No APG pattern applies.

Keyboard

KeyAction
TabNot focusable.

Focus

None; if a badge needs to be pressed it is a chip.

Labelling

The text is the label; the dot is aria-hidden. Never convey status by colour alone: the word says it.

Content

  • One or two words, sentence case: "Done", "Offline". Uppercase is never typed into the source.
  • Counts use digits; cap at "99+" with the full number in the label.
  • Use the product's words: "Done" and "Active" match the filters (L2-025.2).
