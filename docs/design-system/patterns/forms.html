Pattern

Forms

Two one-field forms, one rule: never lose what the person typed, and explain every rejection at the field.

Overview

Tasks has two forms and both are one field long: the composer that adds a task and the inline edit that renames one. The pattern is the same for both: type, press Enter, see the result immediately; anything that cannot be saved is explained at the field, in one sentence, and the typed text is never lost.

  • Validation is local first: an empty or whitespace-only title is rejected before any request is sent (L2-002.1, L2-013.2).
  • The 200-character limit is enforced by maxlength and made visible by a quiet counter from 160 characters (L2-002.2, L2-002.3).
  • Server validation (HTTP 422, RFC 9457 problem details) is shown as is, at the field (L2-004.4).
  • Failures keep the text: a rejected add leaves the title in the composer; a rejected edit restores the previous title (L2-004.3, L2-013.4).

Components: Composer, Text field, Form field, Inline message, Button, Task item. Longer forms (settings, sign-in) are not part of v1; Form layout documents how they would be built.

Structure

The composer sits first in the card; the inline edit replaces a row's title in place. Both use the same input, focus halo and error message.

  1. Label: the composer's label "New task" is visually hidden; the placeholder "What needs doing?" is a hint, not the label (L2-029.3). The edit input is named "Edit task title".
  2. Field: .input--filled.input--lg in the composer (18px text, no iOS zoom), .input in the row.
  3. Counter: .field__count inside the field, shown from 160 characters, red at 200/200.
  4. Action: one primary button, collapsed to its plus icon below SM.
  5. Message: .message--error directly under the field, linked by aria-describedby, announced with role="alert".

Responsive behaviour

  • XS (< 576px): the Add task button collapses to a 52px square with the plus icon (.btn--collapse); its name stays "Add task" through aria-label.
  • SM and up: the button shows its label; the field takes the remaining width.
  • Inputs use 18px text at every size so iOS never zooms on focus (L2-028.3).
  • Rotating the device keeps the composer text and the edit state (L2-028.4): state lives in the component, not the layout.
  • Long edits wrap nowhere: the edit input scrolls horizontally inside itself, the row's height does not jump.

Accessibility

  • Labels: every field has a programmatic name ("New task", "Edit task title"). Placeholders are hints only.
  • Errors: aria-invalid="true" on the field, the message linked with aria-describedby and rendered with role="alert", so it is announced once without moving focus. Error text names the problem and the fix (WCAG 3.3.1, 3.3.3).
  • Keyboard: / focuses the composer from anywhere outside a field; Enter submits; in a row, Enter on the title edits, Enter saves and Esc cancels, then focus returns to the title (L2-023, L2-031.4).
  • No disabled submit: the Add task button is never disabled; activating it on empty text explains the problem instead (L2-008.6).
  • Motion: the shake on an empty submit is removed with prefers-reduced-motion; the message carries the meaning.
