Routes, Form Requests and the thin controller

Attribute routing, model binding and FluentValidation, mapped onto the HTTP layer

What you will be able to answer

  1. How the seven endpoints are declared, and why their order matters
  2. What a Form Request is, versus data annotations or FluentValidation
  3. How a controller method receives validated input and a use case with no registration
  4. Why the controller takes the id as a string instead of binding a model

routes/api.php

backend/routes/api.php
Route::prefix('v1')->group(function (): void {
    Route::get('todos', [TodoController::class, 'index']);
    Route::post('todos', [TodoController::class, 'store']);
    // Static paths first, so `completed` and `restore` are never read as an id.
    Route::delete('todos/completed', [TodoController::class, 'destroyCompleted']);
    Route::post('todos/restore', [TodoController::class, 'restoreMany']);
    Route::patch('todos/{todo}', [TodoController::class, 'update'])->whereUlid('todo');
    Route::delete('todos/{todo}', [TodoController::class, 'destroy'])->whereUlid('todo');
    Route::post('todos/{todo}/restore', [TodoController::class, 'restore'])->whereUlid('todo');
});
  • Attribute routing moved into one file: [Controller::class, 'method'] per route, controllers only, never closures
  • Mounted under /api by withRouting(api:), so the group yields /api/v1/...

Order matters

ASP.NET Core endpoint routing

  • Literal segments score above parameters automatically
  • todos/completed wins over todos/{id} whatever the declaration order

Laravel

  • First registered match wins
  • todos/{todo} declared first would read completed as an id
  • Hence the comment: a tidy-up reorder would break the API

whereUlid is your {id:guid}

Route::patch('todos/{todo}', [TodoController::class, 'update'])->whereUlid('todo');
C# 
[HttpPatch("{id:guid}")]
public IActionResult Update(Guid id, UpdateTodoRequest body)
  • A malformed id matches no route: 404 before any database work
  • Requirement L2-014 criterion 4: a bad id is a 404, not a 500
  • Verified by UpdateTodoTest: "returns 404 problem details for an unknown, deleted, or malformed id"

Form Requests

  • One class per endpoint with input, in app/Http/Requests/Api/V1
  • rules() returns field → rule list
  • Validated when the container resolves it for the controller method
  • Failure throws ValidationException → 422 problem details with errors
  • No ModelState checks, ever
ApproachRules live inTyped values
Data annotationsDTO attributesthe DTO
FluentValidationa validator classthe DTO

StoreTodoRequest

backend/app/Http/Requests/Api/V1/StoreTodoRequest.php
/**
 * A title is 1 to 200 characters after trimming (L2-002). The global TrimStrings
 * and ConvertEmptyStringsToNull middleware trim it first, and `max` counts characters.
 */
final class StoreTodoRequest extends FormRequest
{
    /**
     * @return array<string, mixed>
     */
    public function rules(): array
    {
        return [
            'title' => ['required', 'string', 'max:200'],
        ];
    }

    public function title(): string
    {
        return $this->string('title')->toString();
    }
}
  • Whitespace-only becomes null through the middleware and fails required
  • max:200 counts Unicode characters: 200 emoji pass
  • The controller calls $request->title(): never all(), never input('title')
  • Larastan sees a string at the call site

ListTodosRequest: an enum as the binder

backend/app/Http/Requests/Api/V1/ListTodosRequest.php
public function rules(): array
{
    return [
        'status' => ['sometimes', 'string', Rule::enum(TodoStatus::class)],
    ];
}

public function status(): TodoStatus
{
    return $this->enum('status', TodoStatus::class) ?? TodoStatus::All;
}
  • sometimes: validate only when present
  • Rule::enum: the value must be a backing value of TodoStatus
  • The accessor returns the enum, defaulting to All
  • ?status=bogus → 422 with a status error (ListTodosTest)

UpdateTodoRequest: a partial update

backend/app/Http/Requests/Api/V1/UpdateTodoRequest.php
public function rules(): array
{
    return [
        'title' => ['required_without:completed', 'string', 'max:200'],
        'completed' => ['required_without:title', 'boolean:strict'],
    ];
}

/**
 * @return array{title?: string, completed?: bool}
 */
public function changes(): array
{
    $changes = [];
    if ($this->has('title')) {
        $changes['title'] = $this->string('title')->toString();
    }
    if ($this->has('completed')) {
        $changes['completed'] = $this->boolean('completed');
    }

    return $changes;
}
  • Each field is required only when the other is absent: {} fails
  • boolean:strict rejects "yes" and 1; JSON true passes
  • changes() carries only the keys that were sent, typed by an array shape
  • .NET: nullable properties with a JsonIgnore condition, or JSON Patch

RestoreTodosRequest: wildcard rules and a custom rule

backend/app/Http/Requests/Api/V1/RestoreTodosRequest.php
public function rules(): array
{
    return [
        'ids' => ['required', 'array', 'list', 'min:1', 'max:500', $this->distinct(...)],
        'ids.*' => ['required', 'string', 'ulid'],
    ];
}

/**
 * One pass over the list; the per-item `distinct` rule compares every pair, which
 * costs too much at 500 ids (L2-038).
 */
private function distinct(string $attribute, mixed $value, Closure $fail): void
{
    if (is_array($value) && count($value) !== count(array_unique(array_map(
        fn (mixed $id): mixed => is_string($id) ? strtolower($id) : $id,
        $value,
    ), SORT_REGULAR))) {
        $fail('The :attribute field must not contain duplicates.');
    }
}
  • ids.* validates every element
  • A closure rule receives the attribute, the value, and a $fail callback
  • The comment names the rejected alternative and why: the built-in distinct is quadratic
  • No authorize(): single-user project, and a missing method means authorised

The thin controller

backend/app/Http/Controllers/Api/V1/TodoController.php
final class TodoController extends Controller
{
    public function index(ListTodosRequest $request, ListTodos $listTodos): TodoCollection
    {
        return new TodoCollection($listTodos->handle($request->status()));
    }

    public function store(StoreTodoRequest $request, CreateTodo $createTodo): JsonResponse
    {
        $todo = $createTodo->handle($request->title());

        return (new TodoResource($todo))->response()
            ->setStatusCode(201)
            ->header('Location', url("/api/v1/todos/{$todo->id}"));
    }

    public function update(UpdateTodoRequest $request, string $todo, UpdateTodo $updateTodo): TodoResource
    {
        return new TodoResource($updateTodo->handle($todo, $request->changes()));
    }

    public function destroy(string $todo, DeleteTodo $deleteTodo): Response
    {
        $deleteTodo->handle($todo);

        return response()->noContent();
    }

Why the id stays a string

Implicit route model binding (not used)

public function update(
    UpdateTodoRequest $request,
    Todo $todo,
)
  • Framework loads the row and 404s if missing
  • Cannot express "deleted is 404 for update, but valid for restore" per route without configuration
  • Pulls Eloquent into the HTTP layer

What this backend does

public function update(
    UpdateTodoRequest $request,
    string $todo,
    UpdateTodo $updateTodo,
)
  • The Action owns the not-found rule: find() or findDeleted(), then TodoNotFound
  • Unit-testable with the in-memory fake
  • Same instinct as passing an id, not an entity, to a MediatR handler

Pitfalls

  1. Reordering routes so {todo} precedes completed or restore
  2. $request->all() or input() in a controller: unvalidated keys slip through
  3. boolean instead of boolean:strict: "yes" becomes a completion flag
  4. Route model binding, then a 404 on restore for a deleted todo
  5. "Just one line" of logic in a controller: the ten-line cap makes it visible in review

Things to remember

  • Routes: explicit, ordered, constrained with whereUlid, controllers only
  • Form Requests: FluentValidation plus typed accessors, validated before the controller runs
  • Controller: method injection, one Action call, one Resource, ten lines
  • Ids: stay strings so the Action owns the not-found rule
