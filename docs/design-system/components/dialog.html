Dialog

A modal window for one decision or one short form. Not used in v1: the product undoes instead of confirming.

Overview

A dialog interrupts the page to ask for one decision or one short piece of input, and nothing else can be used until it is answered or dismissed.

Not used in v1. L2-022 keeps the app to one screen with no modals. Destructive actions are reversible instead of confirmable: deleting a task or clearing completed tasks shows a toast with Undo (L2-015, L2-017), which is faster and safer than a confirmation step. The dialog is documented so a future screen that genuinely needs one (for example, a destructive action that cannot be undone) builds it the same way (D22).

  • Prefer an inline edit, an Undo toast, or a new page before reaching for a dialog.
  • Use the destructive variant only for irreversible actions; use form for one or two fields; use scrollable when the body is longer than the viewport.
  • Never open a dialog on page load or stack one dialog on another.

Anatomy

  1. Title--text-h3; a question for destructive dialogs. It labels the dialog (aria-labelledby).
  2. Close buttonGhost icon button, aria-label="Close". Omitted on destructive dialogs, where Cancel is explicit.
  3. BodyMuted text or a short form; --space-4 / --space-6 padding.
  4. FooterActions aligned to the end, primary last; sticky on scroll.

In dark the dialog uses --color-bg-surface-raised (--palette-ink-850), one step lighter than cards, and --shadow-4; the backdrop is --color-bg-backdrop.

Responsive behaviour

  • XS (< 576px): bottom sheet. Full width, --radius-xl on the top corners only, max-height: 90dvh, footer sticky at the bottom so the action is always reachable.
  • SM and up (≥ 576px): centred, calc(100% - 32px) wide up to its size's max width.
  • Footer buttons wrap when the row is too narrow; the primary action stays last.
  • Long content scrolls inside .dialog__body (.dialog--scroll), never the page behind.

Theming

Reads --color-bg-surface-raised, --color-fg-default, --color-fg-muted, --shadow-4, --radius-xl, --color-bg-backdrop; the destructive icon reads --color-danger-bg and --color-danger-icon. Override --dialog-width for a custom width.

.dialog--wide { --dialog-width: 56rem; }

Accessibility

Role and pattern

Native <dialog> opened with showModal(), following the APG Dialog (Modal) pattern. showModal() supplies the modal role, the backdrop, the top layer and makes the rest of the page inert. Destructive confirmations use role="alertdialog" and aria-describedby on the body.

Keyboard

KeyAction
Tab / Shift+TabCycle through the dialog's controls only; focus never reaches the page behind.
EscCloses the dialog (the native cancel event) and returns focus. A busy dialog ignores Esc until the request settles.
EnterSubmits a form dialog from inside a field.

Focus

On open, focus moves to the first field in a form dialog, to Cancel in a destructive dialog (the safe choice), otherwise to the primary action. On close, focus returns to the control that opened it. The ring is the shared 2px --color-focus-ring.

Labelling

aria-labelledby points at the title; destructive dialogs add aria-describedby pointing at the body sentence. The close button is aria-label="Close".

Motion

The dialog rises 16px and fades in over --duration-slow with --ease-enter; with reduced motion it appears instantly.

Touch

Footer buttons are 44px tall; on phones the sheet keeps them at the bottom of the screen, within thumb reach. Tapping the backdrop closes non-destructive dialogs only.

Content

  • Title: a question for decisions ("Delete 3 completed tasks?"), a noun phrase for information ("Keyboard shortcuts").
  • Body: one or two sentences saying what will happen and whether it can be undone. No apologies, no "Are you sure?" (L2-025).
  • Buttons repeat the verb of the title: "Delete tasks" and "Cancel", never "Yes" / "No" or "OK".
