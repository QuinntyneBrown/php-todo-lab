Text field

A text field takes one line of text. In Tasks it is where every task starts ("What needs doing?") and where a title is edited in place.

WCAG 2.2 AAStatus: stableUsed in v1Native <input>

Overview

Use a text field for short free text: a task title, a search term, a name. Use a textarea when the text runs to several lines, and a select when the answer comes from a known list.

  • Filled (.input--filled) sits on a sunken tint and is the composer's field. It brightens to the surface when focused.
  • Default sits on the surface. It is the in-place edit field and every field inside a form.

The input is wrapped by form field for its label, hint, message and counter; the composer composes it with Add task (see composer).

Anatomy

  1. Label.field__label, visible or visually hidden ("New task" in the composer), always programmatic.
  2. Container.input: 44px (md), 1.5px --color-border-strong edge, 12px radius.
  3. Value / placeholder18px (--text-body-lg) so iOS never zooms (L2-028.3). Placeholder is a hint, not the label.
  4. Counter (optional).field__count: appears at 160 characters; red and semibold at 200/200.

Counter and limit

165/200
200/200
From 160 characters a quiet counter appears (L2-002.3); at 200/200 it turns red and maxlength stops typing (L2-002.2).

Both themes

  • Focus replaces the outline ring with an accent edge and a 3px --shadow-focus halo; the edge alone is 4.5:1 or more against the surface.
  • Invalid uses aria-invalid="true": danger edge and halo, plus a message linked by aria-describedby. Colour is never the only signal.
  • Read-only keeps the value selectable and focusable; disabled removes it from the tab order. v1 uses neither: the composer stays usable even while loading or offline (L2-008, L2-042).

Responsive behaviour

  • Fields are fluid: they fill their container at every breakpoint and never set a fixed width.
  • The value stays at 18px (16px for small) at every size so iOS never zooms on focus (L2-028.3).
  • Rotating the device keeps the typed text and edit state (L2-028.4); nothing re-renders on resize.
  • Composer at XS: the field takes all the width beside the 52px icon-only Add task.

Theming

Component tokens --input-bg, --input-border and --input-height alias --color-bg-surface (or --color-bg-surface-sunken when filled), --color-border-strong and --control-height-md. Each state swaps the token, not the property, so a re-skin overrides one variable.

.composer .input { --input-bg: var(--color-bg-surface-sunken); }

Accessibility

Role and pattern

Native <input type="text|search|password|email">; no ARIA role. Errors follow the error identification technique with aria-invalid and aria-describedby.

Keyboard

KeyAction
TabInto and out of the field.
EnterComposer: submits Add task. In-place edit: saves.
EscIn-place edit: cancels and restores the title (L2-012).

Focus

The composer has focus on load except on touch devices (L2-022.3). Focus is drawn as an accent edge plus halo instead of the outline ring; in forced-colors mode the system ring returns.

Labelling

Every field has a label: the composer's "New task" is visually hidden but programmatic (L2-029.3); the editor uses aria-label="Edit task title". The placeholder "What needs doing?" is a hint and is not announced as the name. The counter and errors are linked with aria-describedby; field errors use role="alert".

Motion

Edge, fill and halo transition over 150ms. An empty submit shakes the field once (.composer--shake, 250ms); reduced motion removes the shake and keeps the message.

Touch

44px and 52px heights; the whole field is the target.

Content

  • Labels are nouns in sentence case: "New task", "Task title".
  • Placeholders ask or show an example: "What needs doing?". Never put instructions only in the placeholder.
  • Errors say what to do: "Enter a task title.", "A task needs a title." Server messages are shown as they arrive (L2-004.4).
  • Counters read "165/200": no words, tabular numerals.
