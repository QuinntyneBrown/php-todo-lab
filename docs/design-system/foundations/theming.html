Theming

Two themes from one set of semantic tokens. The product follows the operating system; components never know which theme they are in.

Overview

Tasks ships two themes, light and dark, built from the same semantic tokens. The product follows the operating system through prefers-color-scheme and has no manual toggle in v1 (L2-026). The data-theme attribute exists so the mocks (?theme=) and this documentation can show both themes side by side.

How themes work

  1. Light is :root. Every semantic token has its light value there, and color-scheme: light so native controls and scrollbars match.
  2. Dark overrides the semantic tier only, in two identical blocks: [data-theme="dark"], and @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }. The second makes the OS preference win unless a page forces light. Both set color-scheme: dark.
  3. Components never branch on theme. They read var(--color-…) and get the right value; components.css contains no theme selectors.
  4. Any element can carry data-theme, which is how the side-by-side samples on these pages work. ds.js resolves live token values inside the nearest [data-theme].
/* tokens.css (abridged) */
:root { --color-bg-surface: var(--palette-white); color-scheme: light; }
[data-theme="dark"] { --color-bg-surface: var(--palette-ink-900); color-scheme: dark; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --color-bg-surface: var(--palette-ink-900); color-scheme: dark; }
}

No flash of the wrong theme: tokens are plain CSS loaded in <head>, so the first paint already uses the OS scheme (L2-026.1). Nothing waits for JavaScript.

How dark differs from light

  • Dark is built from roles, not by inverting light. Surfaces get lighter as they rise: canvas ink-950 < surface ink-900 < raised ink-850.
  • The accent lightens (sea-600 → sea-400) and text on it flips to near-black sea-950.
  • The toast stays inverse: dark ink in light mode, pale ink in dark mode, with its Undo action switching from sea-300 to sea-700.
  • Status backgrounds become deep tints with light text; shadows use black at higher opacity because a dark surface cannot cast a visible ink shadow.
  • The segmented indicator uses the raised surface so it stays visible in dark (D9).

Adding a theme

  1. Add any new primitives to the primitives block of tokens/tokens.css.
  2. Add a [data-theme="<name>"] block that overrides semantic tokens only, with color-scheme set. Start by copying the dark block for a dark brand, or nothing for a light one.
  3. Run check_contrast.py tokens/tokens.css; every pair in contrast-pairs.json is checked for the new theme automatically. Fix primitives until it exits 0.
  4. Regenerate tokens.json with tokens_to_json.py; the new theme appears under each token's $extensions.
  5. Review the color page and three component pages with ?theme=<name>.

High-contrast and forced-colours modes are handled in tokens.css too: prefers-contrast: more raises borders and muted text to stronger tokens; forced-colors: active hands the focus ring and borders to system colours.

Consuming tokens.json

tokens/tokens.json is a DTCG export generated from tokens.css: each token has $type and $value, aliases are written {color.accent}, and dark values live under $extensions. Use it to generate platform constants (Sass maps, TypeScript, native) instead of copying hex values.

"color": {
  "accent": {
    "$type": "color",
    "$value": "{palette.sea.600}",
    "$extensions": { "com.agent-toolkit": {
      "css": "--color-accent", "resolved": "#0b7f74",
      "themes": { "dark": { "$value": "{palette.sea.400}", "resolved": "#4fd1bf" } }
    } }
  }
}

The Angular app keeps its own frontend/src/styles/tokens.scss (ported from the mocks). When it adopts this system, it should import tokens.css as-is and keep following prefers-color-scheme only.

Do and don't

The product offers no theme toggle in v1 (L2-026). The toggle in this documentation's navigation is a review aid, like the mocks' ?theme=.

Tokens

Theming has no tokens of its own: it is the mechanism that switches the semantic colour and shadow tokens. Their light and dark values are listed on the color and elevation pages.
