pint.json

backend/pint.json
{
    "preset": "laravel",
    "rules": {
        "declare_strict_types": true,
        "ordered_imports": {
            "sort_algorithm": "alpha"
        },
        "no_unused_imports": true,
        "fully_qualified_strict_types": true
    },
    "exclude": [
        "bootstrap/cache",
        "storage",
        "vendor"
    ]
}
  • laravel preset: PSR-12 + PER coding style + Laravel conventions
  • declare_strict_types: inserts the declaration in every file; L2-044 criterion 5 enforced without a test
  • ordered_imports: alphabetical use statements
  • no_unused_imports: removes dead imports
  • fully_qualified_strict_types: FQCNs in signatures become imports
  • Pint rewrites code, not only whitespace

Review rules that go with Pint (L2-056)

Before every commit

$ composer format         # pint, rewrites files
$ composer format:check   # pint --test, first step of composer check

An unformatted file fails CI before anything else runs.

In review

  • A rule is never disabled without naming it and giving a reason
  • Formatting changes are committed separately from behaviour changes
  • A commit that mixes the two is a request for a split

phpstan.neon

backend/phpstan.neon
includes:
    - vendor/larastan/larastan/extension.neon

parameters:
    level: 8
    paths:
        - app
        - bootstrap/app.php
        - config
        - database
        - routes
        - tests/Fakes
  • Larastan = PHPStan + Laravel knowledge: Todo::query() is a builder of Todo, scopes exist, facades forward, model docblocks declare attributes
  • Levels run 0 to 10 (as of 2026). Level 8: calling a method on a possibly-null value, passing nullable to non-null, returning the wrong shape are errors
  • Nullable reference types with warnings as errors, plus generic checking of docblock types
  • Zero errors, no baseline (L2-044 criterion 5)

Load-bearing annotations

backend/app/Repositories/EloquentTodoRepository.php
return DB::transaction(function (): array {
    /** @var list<string> $ids */
    $ids = Todo::query()->completed()->lockForUpdate()->pluck('id')->all();
backend/app/Repositories/TodoRepository.php
/**
 * @return Collection<int, Todo>
 */
public function list(TodoStatus $status): Collection;

/**
 * @return array{active: int, completed: int}
 */
public function counts(): array;
  • Inline @var narrows array<int, mixed> to list<string> where the code knows better
  • TodoFactory is @extends Factory<Todo>; the model's HasFactory carries @use HasFactory<TodoFactory>
  • Remove the @return on counts and ListTodos fails: $counts['active'] is no longer an int
  • Annotations are code. Review them like signatures.

What a level 8 failure looks like

Illustrative change 
public function handle(string $id): void
{
    $this->todos->delete($this->todos->find($id));
}
$ composer analyse
  Line   Actions/Todos/DeleteTodo.php
  17     Parameter #1 $todo of method TodoRepository::delete()
         expects App\Models\Todo, App\Models\Todo|null given.
 [ERROR] Found 1 error
  • The same bug nullable reference types catch in C#
  • Not an @phpstan-ignore, not a baseline entry
  • Output shape shown for illustration; the repository has zero errors
The fix is the guard · backend/app/Actions/Todos/DeleteTodo.php 
public function handle(string $id): void
{
    $this->todos->delete($this->todos->find($id) ?? throw new TodoNotFound($id));
}

composer check: cheapest first

format:check ~1 s
→
analyse seconds
→
test a minute, with MySQL
→
green
backend/composer.json
"check": [
    "@format:check",
    "@analyse",
    "@test"
]

Stops at the first failure. Run it before every push; the pull request template asks you to confirm you did.

CI runs the same command against MySQL 8.4

.github/workflows/ci.yml
jobs:
  backend:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.4
        env:
          MYSQL_ROOT_PASSWORD: secret
          MYSQL_DATABASE: todo_test
          MYSQL_USER: todo
          MYSQL_PASSWORD: secret
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1 -psecret"
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
          extensions: pdo_mysql, mbstring, intl
          coverage: pcov
      - run: composer install --no-interaction --prefer-dist
      - run: cp .env.example .env && php artisan key:generate
      - run: composer check
  • backend and frontend jobs run in parallel on every push to main and every pull request
  • A MySQL 8.4 service with todo_test and a health check: the job waits until it answers
  • PHP 8.4 with pdo_mysql, mbstring, intl, and pcov for the coverage gate
  • Then exactly what you ran locally: green CI means your machine was green

.editorconfig and .gitattributes

.editorconfig
[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

# PSR-12 / PER Coding Style: four-space indent for PHP (Laravel Pint enforces the rest).
[*.php]
indent_size = 4
.gitattributes
# Normalise every text file to LF in the repository and the working tree, on every OS.
# Pint (PSR-12 line_ending) and Prettier (endOfLine: lf) both require LF.
* text=auto eol=lf

*.bat  text eol=crlf
*.cmd  text eol=crlf
*.ps1  text eol=crlf

Without this, a Windows checkout with core.autocrlf would fail Pint's line_ending rule (L2-056 criterion 5).

Pitfalls

  1. An @phpstan-ignore comment or a baseline file
  2. A Pint rule disabled without a name and a reason
  3. Pint on one file, while CI formats the whole tree
  4. A reformat mixed into a behaviour commit
  5. Removing a docblock because "it compiles": nothing compiles; Larastan checks the docblock
  6. Treating a nullable-access error as noise

Things to remember

  • Pint: Laravel preset + strict types, sorted imports, no unused imports, qualified types imported; format before committing, commit formatting separately
  • Larastan: level 8, fed by mandatory docblocks, zero errors, no baseline
  • check: format, analyse, test, cheapest first; CI runs the same against MySQL 8.4
  • Settings: .editorconfig and .gitattributes keep indentation and LF stable everywhere
