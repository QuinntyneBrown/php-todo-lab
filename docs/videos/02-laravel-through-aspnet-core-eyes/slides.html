The front controller

backend/public/index.php
define('LARAVEL_START', microtime(true));

// Determine if the application is in maintenance mode...
if (file_exists($maintenance = __DIR__.'/../storage/framework/maintenance.php')) {
    require $maintenance;
}

// Register the Composer autoloader...
require __DIR__.'/../vendor/autoload.php';

// Bootstrap Laravel and handle the request...
/** @var Application $app */
$app = require_once __DIR__.'/../bootstrap/app.php';

$app->handleRequest(Request::capture());
  • Every path is routed to this file by the web server or php artisan serve
  • Autoloader, then application, then handleRequest
  • The equivalent of the generated Main that calls CreateBuilder and app.Run()

Auto-wiring by reflection

backend/app/Http/Controllers/Api/V1/TodoController.php
public function store(StoreTodoRequest $request, CreateTodo $createTodo): JsonResponse
{
    $todo = $createTodo->handle($request->title());

    return (new TodoResource($todo))->response()
        ->setStatusCode(201)
        ->header('Location', url("/api/v1/todos/{$todo->id}"));
}
  • A concrete class in a constructor or method signature is built on demand, recursively
  • No registration for concretes: CreateTodo is never listed anywhere
  • Method injection on controller actions and Artisan commands is normal, not [FromServices]

One project, many folders

.NET Clean Architecture

  • Domain, Application, Infrastructure, Web projects
  • Project references enforce the dependency direction
  • The compiler rejects Domain → Infrastructure

This Laravel backend

  • One project; layering is by folder and convention
  • Held by AGENTS.md, Larastan, and code review
  • Nothing stops an Action from querying Todo except the reviewer

Pitfalls

  1. env() outside config/ works locally and breaks once configuration is cached
  2. A facade or app() inside an Action breaks the dependency direction the unit tests rely on
  3. Your own providers must be listed in bootstrap/providers.php; only packages are discovered
  4. Edited .env and nothing changed? Check whether configuration is cached

Things to remember

  • Bootstrap: index.php is Main; bootstrap/app.php is Program.cs: routing, middleware, exception rendering in one call
  • Container: concretes auto-wire; interfaces bind in AppServiceProvider::$bindings
  • Facades and helpers: service location; fine in infrastructure, never in Actions
  • Config: arrays under config/, read with config(), fed by .env via env() in config files only
  • Checks: composer check must pass
