An Action is a handler without the mediator

PHP · app/Actions/Todos/CreateTodo.php 
final readonly class CreateTodo
{
    /** The most non-deleted todos the list may hold (L2-003). */
    public const int LIMIT = 500;

    public function __construct(private TodoRepository $todos) {}

    public function handle(string $title): Todo
    {
        return $this->todos->createWithinLimit($title, self::LIMIT);
    }
}
C# · MediatR 
public record CreateTodoCommand(string Title) : IRequest<Todo>;

public sealed class CreateTodoHandler(ITodoRepository todos)
    : IRequestHandler<CreateTodoCommand, Todo>
{
    public const int Limit = 500;

    public Task<Todo> Handle(CreateTodoCommand c, CancellationToken ct) =>
        todos.CreateWithinLimitAsync(c.Title, Limit, ct);
}

// controller: await mediator.Send(new CreateTodoCommand(title));
  • No command object: the handle parameters are the command
  • No Send: the controller calls the injected Action directly

What you lose, what you keep

Not here

  • Pipeline behaviours for logging, validation, transactions
  • A mediator decoupling caller from handler

Each concern has an explicit home instead: Form Requests validate, the repository owns transactions.

Kept

  • One class, one public handle, one interface dependency (L2-044)
  • Unit tests build an Action with new InMemoryTodoRepository: no database, no mocks

UpdateTodo: a rule, a comment, a requirement id

backend/app/Actions/Todos/UpdateTodo.php
public function handle(string $id, array $changes): Todo
{
    $todo = $this->todos->find($id) ?? throw new TodoNotFound($id);

    $columns = [];
    if (array_key_exists('title', $changes)) {
        $columns['title'] = $changes['title'];
    }
    // Always written when requested, so a concurrent request cannot leave this
    // one half-applied (L2-043); `??` keeps an existing completedAt (L2-009).
    if (array_key_exists('completed', $changes)) {
        $columns['completed_at'] = $changes['completed'] ? ($todo->completed_at ?? now()) : null;
    }

    return $this->todos->update($todo, $columns);
}
  • Load or throw TodoNotFound
  • Only the keys that were sent become columns
  • ?? keeps an existing completed_at: completing twice is idempotent (L2-009 criterion 3)
  • Always written when requested, so concurrent PATCHes apply in full (L2-043)
  • Review pattern: a short comment citing the L2 id next to the non-obvious line

Delete and Restore: different not-found rules for the same id

backend/app/Actions/Todos/DeleteTodo.php
public function handle(string $id): void
{
    $this->todos->delete($this->todos->find($id) ?? throw new TodoNotFound($id));
}
backend/app/Actions/Todos/RestoreTodo.php
public function handle(string $id): Todo
{
    return $this->todos->restore($this->todos->findDeleted($id) ?? throw new TodoNotFound($id));
}
  • find sees live rows; findDeleted sees trashed rows. Same id, opposite answers.
  • This is why the controller passes a string and never binds a model

The bulk pair

backend/app/Actions/Todos/ClearCompletedTodos.php
/**
 * Soft-deletes every completed todo in one transaction (L2-017, L2-043).
 *
 * @return list<string> the ids deleted, so the client can undo
 */
public function handle(): array
{
    return $this->todos->deleteCompleted();
}
backend/app/Actions/Todos/RestoreTodos.php
/**
 * Restores the soft-deleted todos among `$ids` in one transaction; others are ignored.
 *
 * @param  list<string>  $ids
 * @return Collection<int, Todo>
 */
public function handle(array $ids): Collection
{
    return $this->todos->restoreMany($ids);
}

Each delegates to one repository method, because each needs a transaction the Action must not know about.

What no Action does

  • Imports the Todo query builder
  • Uses a facade
  • Catches an exception to return null
  • Has a second public method

If a pull request adds any of these, the layering is broken, and the unit tests with the fake are the first thing to fail.

TodoRepository: eleven methods, each a sentence

backend/app/Repositories/TodoRepository.php
interface TodoRepository
{
    /**
     * Non-deleted todos matching the status, newest first, ties broken by id descending.
     *
     * @return Collection<int, Todo>
     */
    public function list(TodoStatus $status): Collection;

    /**
     * Counts of all non-deleted todos.
     *
     * @return array{active: int, completed: int}
     */
    public function counts(): array;

    /**
     * Creates a todo unless `$limit` non-deleted todos already exist. The check and the
     * insert are atomic, so concurrent creates cannot exceed the limit (L2-043).
     *
     * @throws TodoLimitReached
     */
    public function createWithinLimit(string $title, int $limit): Todo;

    /** The non-deleted todo with this id, if any. */
    public function find(string $id): ?Todo;

    // ... update, delete, findDeleted, restore, deleteCompleted, restoreMany, purgeDeletedBefore

Compared with ITodoRepository in Application

Shaped by use cases

No generic GetAll/Save. createWithinLimit, deleteCompleted, purgeDeletedBefore: one method per need, so the fake stays small and honest.

Owns transactions

No unit-of-work behaviour in a pipeline. The repository method opens the transaction; the in-memory fake simply does not need one.

Returns Eloquent models

Active Record: the model is entity and mapper. A choice, not an accident. The model carries only a completed accessor and two scopes; Actions treat it as data.

Adding a use case, adding a filter

New use case

  1. Action class in app/Actions/Todos
  2. Repository method, if the contract needs one, plus the fake
  3. Route, Form Request, controller method
  4. Unit test with the fake, feature test over HTTP

New filter (L2-044 criterion 6)

  1. New TodoStatus case
  2. New scope on Todo
  3. One new arm in the repository's match
  4. A test

ListTodos, ListTodosRequest, and the controller do not change.

Pitfalls

  1. Injecting the Todo model or a query builder instead of the interface
  2. A second public method because two endpoints felt related
  3. A loose array where a readonly result class like TodoList belongs
  4. Catching TodoNotFound to return null: hides the 404 from the renderer
  5. DB::transaction in an Action: couples it to the database and breaks the in-memory tests

Things to remember

  • Action: a handler without the mediator; one class, one handle, one interface; parameters are the command
  • Rules: business rules in Actions; atomic persistence mechanics in the repository
  • Port: shaped by use cases, owns transactions, returns Eloquent models by choice
  • Exceptions: carry data, mapped once in the renderer
  • Extending: add code, modify no existing Action
