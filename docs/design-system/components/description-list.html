Description list

Label–value pairs that describe one thing, such as a task's title, status and created time.

WCAG 2.2 AAStatus: stableNot used in v1

Overview

A description list shows the properties of one thing as label–value pairs: a task's title, status, created time and id. It is the right element when the labels are fixed and the values vary.

  • Use a table to compare several things; use a list for a set of similar items.
  • v1 shows tasks only as rows, so this component is not used yet; it is ready for a task detail or settings view. Its data comes from the v1 task resource (ULID id, ISO 8601 UTC timestamps).

Anatomy

  1. Term<dt>, --text-label, --color-fg-muted.
  2. Description<dd>, body text; may hold a badge, time or code.

Sizes

Description lists inherit the body size; there is one size.

States

Description lists are static; they have no interactive states. Values can be empty, shown as an em dash with a visually hidden "None".

Responsive behaviour

  • XS: always vertical (term above value), so long values never squeeze the term.
  • SM and up: .dl--horizontal puts terms in a minmax(8rem, max-content) column with hairline dividers.
  • Values wrap; ids and codes use overflow-wrap: anywhere through the code style.

Theming

Reads --color-fg-muted for terms, --color-fg-default for values and --color-border-default for the horizontal dividers. No component tokens; both themes follow the semantic tier.

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>; screen readers announce term and definition pairs. No ARIA pattern needed.

Keyboard

KeyAction
TabSkips the list unless a value contains a link or button.

Focus

Only interactive content inside a value takes focus, with the shared ring.

Labelling

The terms are the labels. Give the whole list a heading immediately before it. Times use <time datetime> with the UTC value.

Motion

None.

Touch

No targets of its own.

Content

  • Terms are nouns in sentence case without colons: "Created", not "Created:".
  • Dates read as the app writes them: "7 October, 09:12" in the user's locale, with the ISO value in datetime.
  • Show raw ids only where people need to quote them, in code style.
