Skeleton

Grey placeholders in the shape of the task rows while the list loads.

Overview

A skeleton is a grey placeholder in the shape of content that is on its way. The product shows three skeleton rows in the card while the list loads; the header, composer and filters are already there and usable (L2-008.1). The gentle shimmer is the only thing on the page that moves on load (L2-024.1).

  • Use a skeleton when the layout of the coming content is known (a list of rows).
  • Use a spinner for a single control, and the banner if loading fails.
  • Never skeleton something that is already usable, like the composer.

Anatomy

  1. Circle24px, stands in for the checkbox; inset to line up with the real one.
  2. Bar14px tall, fully rounded; widths cycle 58%, 72%, 44% so it reads as text.
  3. Row60px minimum height and a hairline divider, the same as a task row.

Variants

Primitives: title, text, circle, rect. All are aria-hidden.
HTML
<span class="skeleton skeleton--title"></span>
<span class="skeleton" style="--skeleton-width: 80%"></span>
<span class="skeleton skeleton--circle"></span>
<span class="skeleton skeleton--rect"></span>

Composed: task rows

Loading tasks

Three rows, the product's loading state (L2-008.1). The status text is visually hidden.
HTML
<p class="visually-hidden" role="status">Loading tasks</p>
<ul class="skeleton-list" aria-hidden="true">
  <li class="skeleton-row"><span class="skeleton skeleton--circle"></span><span class="skeleton"></span></li>
  …three rows…
</ul>

Sizes

Skeletons take the size of what they replace. Text bars are 14px; titles 20px; circles 24px; rectangles 96px by default. Width is set with --skeleton-width.

--skeleton-width: 30%, 60%, 90%.

States

Skeletons are not interactive. Two states: shimmering, and static under reduced motion. They are removed, not faded, when content arrives.

Responsive behaviour

  • Rows span the card at every breakpoint; bar widths are percentages, so they scale with the column (560 / 640px).
  • Show exactly three rows regardless of viewport: enough to read as a list without suggesting a count.

Theming

The shimmer is a gradient from --color-border-default through --color-bg-surface-sunken and back, so it is a quiet light sweep in the light theme and a dim one in dark. Override --skeleton-width per element; colours come from semantic tokens only.

Accessibility

Role and pattern

The skeleton list is aria-hidden="true". A separate visually hidden role="status" paragraph says "Loading tasks" once; when the list arrives, the count is announced by the polite live region. Alternatively set aria-busy="true" on the list container while loading.

Keyboard

Nothing to operate: the component is not focusable.

Focus

Skeletons never take focus. Focus stays in the composer, which is usable while the list loads (L2-022.3).

Labelling

One announcement for the whole region ("Loading tasks"), not per row.

Contrast

Bar on card (decorative)
Status text if shown

Motion

A 1.35s linear shimmer (3 × --duration-deliberate). Under prefers-reduced-motion the animation is removed and the bars are a static tone (L2-024.2, D21).

Touch

Not interactive.

Content

  • No text inside skeletons. The hidden status says "Loading tasks".
  • If loading fails after the automatic retries, replace the skeleton with the banner, not an empty state.
